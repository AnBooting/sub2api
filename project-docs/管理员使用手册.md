## 1. 价格体系：源价 → 基础 Credit → 倍率 → 最终售价

### 1.1 四层口径

| 层 | 含义 | 存放位置 |
|---|---|---|
| 源价格 | 厂商/价格源给的原始价，**保留币种**（国模 CNY、外模 USD）与计量单位 | 价格管理页 / 价表数据 |
| 基础 Credit 单价 | 源价数字**等值映射**，不换汇（源价 2 → 基础价 2 Credit） | 价格管理页 |
| 分组倍率 | 商业售价杠杆；可含峰谷倍率、视频独立倍率 | 分组表单 |
| 最终售价 | 基础价 × 实际服务分组的有效倍率 | 使用记录/快照里体现 |

**充值比例固定 ¥1 = 1 Credit**，不随汇率浮动；平台也不会自动调整你的商业售价。

### 1.2 国模人民币价格源

（路径：/admin/settings → 功能开关 →「模型价格与额度计费」）

- 开关文案：「使用国模人民币价格源」。
- 提示原文：「国模使用原始 CNY 价卡，Claude/GPT 等继续使用 USD 价卡。¥1 和 $1 都扣 1 额度，不做汇率换算；充值到账比例固定为 1。缺少人民币价格的国模需配置手动价格。」
- 开关保存后**即时生效**。

### 1.3 价格同步周期

（同页：「定价同步周期（小时）」）

- 可填 1–720 的整数小时；保存后立即重排定时器，无需重启。
- 留空表示沿用配置文件默认值；页面会显示「当前生效周期：{hours} 小时」。
- **同步状态已在本卡片展示**：USD / CNY 各自「模型数 · 最近更新时间」（从未同步显示"尚未同步"），以及异常提示 `cny_error` / `usd_error` / `deepseek_calendar_error`；页面每 5 秒轮询刷新，并提供「立即同步价格」与「重试」。
- **同步失败不覆盖 Last Known Good Price**：继续用最近一次有效价服务，并记录异常、按现有 Alert/Email 能力通知管理员；同一持续故障会合并/抑制重复通知，不高频刷邮件。
- **币种/单位异常不得静默覆盖**：国模数据出现 USD、或外模数据出现 CNY、或单位映射异常时，保留当前有效价格。

### 1.4 缺价与零价的红线

- **缺价（未定价）**：请求在上游调用前被拒绝（pricing_unavailable），**不允许零成本放行**，也没有"零价放行"开关。
- **显式零价**：按正常价结算为 0，与缺价是两件事，在页面上要能区分。
- 媒体模型的兜底同样禁止：价格页提示「未配置时该模型拒绝放行，不会回落到其它价格。」

### 1.5 缺价清单与价格总表

（路径：/admin/channels → 顶部视图切换「渠道列表 / 价格总表 / 缺价清单」）

- **价格总表（只读）**：汇总当前渠道与分组定价规则里出现过的模型，以及币种、计量单位与各项单价（输入价/输出价/缓存读写价/图片价），并标注价格来源（手工/缺省/价卡）与来源范围（渠道/分组/默认价卡）。支持按模型名与币种过滤。
- **缺价清单**：列出**已配置但价格不完整**的模型，每行说明缺什么（输入价/输出价/缓存价/图片价）、探测结论，并给「去定价」跳转（渠道级跳到该模型的定价编辑处；分组级只能到分组管理页）。
- **检测口径（重要）**：两个视图里的「默认价卡」一列是**前端按当前默认价卡逐模型探测**的结果（`GET /admin/channels/model-pricing`），**可能与实际计费存在差异**，不是权威结论；通配符规则不参与逐模型检测；已命中分组/渠道规则的模型按后端优先级整条规则生效。
- **覆盖范围的硬限制**：默认价卡**只提供单模型查询接口**，没有全站模型总表接口，所以价格总表只列出渠道/分组规则里出现过的模型，不代表全站模型都列全了。
- 探测是前端发起：限并发、可中断、有进度提示，探测失败不阻断页面；空态写「没有检测到缺价模型」，不是「未加载」。

### 1.6 峰谷判定与倍率

- **官方峰谷**只作用在走 DeepSeek 官方价卡的模型/分组上，判定复用计费热路径的同一份实现（`deepseekPeakMultiplierWithCalendar` / `chooseDeepSeekPricingPeriod`），**判定与计费看到同一份假日日历**。
- 判定时区固定 **Asia/Shanghai**；工作日（不含法定节假日）**09:00–12:00** 与 **14:00–18:00** 为峰价（**2 倍**），其余为谷价（**1 倍**）。
- **法定节假日日历优先**：已维护的节假日按谷价；**周末（含调休补班的周末）也按谷价**。
- 节假日日历在定价设置里按年份维护（`PUT /admin/channels/pricing/holidays`，保存需 TOTP 二次确认）。某年**既无自定义日历也无内置覆盖**时，**停用该年的官方峰谷加价**（按谷价计），并在同步状态里报 `deepseek_calendar_error`。
- **分组自定义峰谷窗口优先**：`peak_rate_enabled` / `peak_start` / `peak_end` / `peak_rate_multiplier` 是另一套机制；分组配了自定义窗口时，状态与倍率以分组配置为准。
- **状态只读暴露**：分组 DTO 下发 `deepseek_pricing_state`（`state` = peak/valley/none、`label`、`timezone`、`multiplier`），**不参与计费、不写任何状态**；用户侧分组徽标显示当前峰/谷与生效倍率，管理端分组表单同显。模型广场与可用渠道视图走各自白名单 DTO，**尚未下发该字段**。

## 2. 分组计费配置

（路径：/admin/groups → 新建/编辑分组）

| 配置项 | 说明 | 注意 |
|---|---|---|
| 分组倍率 | 文本/图片等默认倍率 | 是商业售价的主杠杆 |
| 峰谷倍率 | peak_rate_enabled / peak_start / peak_end / peak_rate_multiplier | **不支持跨天**时段；与"DeepSeek 官方峰谷"是两套机制，别混用；**仅订阅类型分组**开放该配置，标准分组需切换计费类型 |
| Realtime 每分钟价格 | 分组表单「Grok Voice 显式定价」区块（USD） | ⚠️ **该区块当前只在 grok 平台分组显示**（`v-if platform === 'grok'`）。OpenAI Live 分组因此**没有单价入口** → 未配置单价时 Live 会话按未计费落库。要给 OpenAI Live 计费，必须先把该字段对所有平台可见 |
| 视频计费 | 按秒 / 按次 二选一，按模型 × 分组 | 按次/图片计费模式必须设置默认价格或至少一个计费层级，否则保存被拦（提示：「按次/图片计费模式必须设置默认价格或至少一个计费层级」） |
| 视频分辨率层级 | 480p / 720p / 1080p 每秒价 | 不同厂商口径不同：Seedance 按 token、Grok 按秒、MiniMax 按次 |
| 视频独立倍率 | 可选，打开后视频不叠加文本倍率 | 按模型族声明计量模式与单价更清晰 |
| 调度策略 | 继承全局 / 单独覆盖 | 见第 3 节 |

**分组配价三原则**：① 同一模型×分组只留一套口径；② 没配价就别开权限（缺价会被拒）；③ 改价只影响新请求，已锁价的请求按旧价结算。

## 3. 调度：全局策略 + 分组覆盖

### 3.1 全局（/admin/settings →「网关调度设置」）

- 「调度策略」选项：**稳定优先 / 平衡 / 响应速度优先**（分组级可另选「继承全局」）。
- 策略提示：「策略影响会话复用时长与粘性等待上限，不放宽并发、安全重试或模型能力约束。」
- 「单请求最大发送次数」「单请求总预算（秒）」（默认 16 次 / 600 秒，含所有真实上游重试；更小的既有限制仍然有效）。
- 「允许未分组 Key 调度」：建议保持关闭，确保每个 Key 都归属明确分组（关闭后未分组 Key 直接 403）。
- 「平台账号自动停调阈值」：账号原生用量窗口达到百分比时临时移出调度，100 表示禁用；支持全局默认 + 单账号覆盖。

### 3.2 分组级（/admin/groups → 分组表单）

- 分组表单里的调度策略下拉支持「继承全局」与三档具体策略，并展示**当前有效策略**（继承时显示全局实际生效值）。
- 优先级：**全局策略 → 分组默认继承或覆盖 → 账号实时状态 → 最终调度**。

### 3.3 故障分类（决定换不换号）

| 情形 | 平台行为 |
|---|---|
| 上游账号/Key 失效、账号限流、满载 | 先换号；组内候选耗尽再换组 |
| 连接或上游暂时故障 | 可安全重试时同样处理 |
| 本站 Key 无效、余额不足、参数错误、模型名无效 | 直接返回错误，**不换号不换组** |
| 内容审核/业务拒绝 | 不重试、不绕道 |
| 超时且无法确认上游是否已执行 | 不盲目重发，优先幂等/查询；无法消除重复风险时返回明确失败 |

**已输出流内容的请求不重放**；图片/视频已提交任务不回退成文本重试。

### 3.4 并发与"不并发/并发过大"排查

两个字段语义不同，**不要混用**：

| 字段 | 作用 |
|---|---|
| 并发数（concurrency） | **硬上限**，原子占用与释放；<=0 表示不限制 |
| 负载因子（load_factor） | 选号时的负载分母，不填则回落并发数 |

排查口诀（对应常见"部分账号不并发、部分并发过大"）：

1. 负载因子 > 并发数 → 负载率虚低 → 一直被打满；
2. 负载因子 < 并发数 → 负载率虚高 → 被过滤掉，表现为"不并发"；
3. 粘性会话 TTL 长 + 粘性权重高 → 流量集中到少数账号；
4. 实时语音（WS）长连接也占并发槽；
5. 槽位 TTL（默认 30 分钟）会让异常退出的请求长时间占位；
6. 账号快照有秒级延迟（outbox 轮询），改完并发数先等一个刷新周期再判断。

## 4. 充值、卡密与订单（运营口径）

### 4.0 先看当前状态：两套体系，一套可用一套未开通

| 体系 | 入口 | 状态 |
|---|---|---|
| **B 自建支付** | /purchase、/orders、/payment/*（alipay / wxpay / stripe / easypay / airwallex） | **可用**。支付成功即到账，订单可查、可取消、可申请退款，断网可用恢复凭据回查 |
| **A 白标商品中心** | /shop → /api/v1/shop/*（云猫适配层） | **未开通**：用户侧只会看到「充值服务尚未开通」 |

A 未开通的技术原因（不是配置疏漏，是适配层尚未落地）：

1. 响应解码器是**预留骨架**，一律 fail closed：返回「上游响应解码器未实现（等待上游接口文档）」；
2. 回调验签同样是预留骨架，验签恒不通过（**回调接口目前恒 401**），支付确认只能靠用户手点「查询最新状态」；
3. 端点路径与凭据只从环境变量读，且请求体字段名/鉴权头仍是 TODO 假设；
4. 商品→卡密→兑换**尚未串起来**：「去兑换」指向的 /redeem 只校验本站 redeem_codes 表，上游卡密没有转换/导入逻辑。

**解封需要上游给出**：商品/下单/查单/发卡接口文档与字段、回调验签算法、鉴权方式、端点路径与站点凭据。拿到后按"只补适配层、不新建支付系统"的原则接入。

**A 体系当前的界面缺口**（无论是否开通都建议补）：

- 订单状态只有 4 种，缺"失败/已取消/已退款/已过期"；
- 「去兑换」与本站兑换码未打通（见上）。

（本轮已补：订单列表与主动回查已接上前端；redirect 支付按服务端已过滤的 redirect_url 真正跳转。）

### 4.1 用户看到的三种订单状态

| 状态 | 含义 | 你的动作 |
|---|---|---|
| 已支付 / 待交付 | 支付成功，卡密未就绪 | 等上游发卡或补发 |
| 已支付 / 交付异常 | 支付成功但取卡密失败 | 按订单号在云猫后台/接口定位并补发；用户不必重新购买 |
| 已交付 | 卡密已可领取 | 无 |

### 4.2 商品同步异常

- 同步失败**不删除**最近一次成功商品数据，商品仍展示，但**服务端暂停新订单创建/购买**，页面提示「商品服务暂时不可用，请稍后重试」。
- 同步恢复后自动恢复购买；已有订单的支付核实、查询、卡密交付不受阻断。
- 用户侧商品中心会显示「上次同步：{time}」。

### 4.3 白标边界

- 用户界面、跳转 URL、嵌入资源**不得出现供应商品牌或域名**；交付异常时只给本站订单号 + 联系站长。
- 本站**不建**支付账本、财务对账、退款与清结算；云猫/渠道侧是资金口径唯一来源。
- 支付成功**不自动兑换、不自动加余额**；兑换走本站既有兑换入口，兑换码只能兑一次。

## 5. 对账与排障

### 5.1 使用记录里要看的字段

- 记录消费（Credit） / 快照最终消费 / 基础单价（Credit） / 已存小计（Credit）
- 实际服务分组、请求分组、故障转移标识、尝试次数
- 定价快照：源价（CNY/USD + 计量单位）、基础 Credit 单价、分组倍率
- 用量明细：输入/输出/缓存 token、图片张数、视频秒数、实时语音时长

### 5.2 三类常见异常与处理

| 现象 | 判定 | 处理 |
|---|---|---|
| 「记录与锁价快照的实际分组或消费不一致」 | 记账与快照存在偏差（页面只呈现两份数据，不会改账） | 停止用户重复提交；用 request_id + 时间窗核对账本，必要时按对账流程纠错 |
| 扣了费但用量记录缺行 | 写日志与结算之间异常 | 账本（usage_billing）为准；Live 结算失败会保留 pending 状态并自动重试，重试金额固定不随时间增长 |
| 请求被拒但没扣费 | 缺价 / 鉴权 / 余额 / 参数类错误，这些**不换号也不结算** | 属预期行为；缺价先补价表再放量 |

### 5.3 用户侧到底能看到什么（回答用户提问时先看这张）

| 主题 | 用户能看到 | 用户看不到 |
|---|---|---|
| 计价单位 | 余额、累计/今日消费、单次消费、Key 额度与 5h/1d/7d 限额、订阅分组日/周/月限额、兑换页、平台配额、批量生图费用 —— 全部 Credit，标签统一带「（Credit）」 | **模型广场单价**仍是源币种 $（源价口径，不换汇），需与账户 Credit 区分 |
| 源价 | 源价格**币种**、计量单位、基础单价（Credit）、锁定倍率、快照最终消费 | **官方源价的金额**（快照只有换算后的基础价）；账号倍率/账号计费成本；上游 request_id；模型映射链 |
| 分组与调度 | 实际服务分组、故障转移四类（无/组内换号/普通组切换/用户授权高可用兜底）、上游发送次数 | 官方源价、账号侧成本 |
| 兜底分组 | 只能看到倍率与开关状态（倍率由管理员设） | 兜底分组的"什么条件下触发"说明 |
| Live | 分组徽标显示「Live」徽标与 Realtime 每分钟单价（标注为源价、非最终扣费）；使用记录明细显示 Live 会话时长与计费口径 | 仍看不到账号侧成本 |
| 视频 | 侧栏「视频任务」/video-tasks 可查自己的任务、状态与**计费模式**（按量/按次/按秒，取自创建时的计费快照），支持游标翻页 | **任务页不提供成片下载**（接口只返回最小字段） |
| 图片 | 批量生图助手入口 + 使用记录里的张数与计费尺寸 | 图片计费口径说明（按次/按张、是否叠加分组倍率）只存在于管理端 locale |

### 5.4 鉴权缓存

- 密钥额度、窗口限额在统一账本里原子累加，变更后由数据库触发器走鉴权缓存失效通道。
- 手工改了 Key 的额度/分组后，缓存生效可能滞后 1 个刷新周期；排障时先等一个周期再判断"没生效"。
