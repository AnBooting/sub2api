# Sub2API 用户使用手册

版本：1.0｜日期：2026-10-21｜适用：Sub2API 站点用户（OpenAI / Claude / 国产模型等中转 API）

> 本手册描述本站当前已上线的计费与调度规则，帮助你知道"钱花在哪、为什么这次比上次贵、失败了怎么查"。
> 界面文案以中文站为准，英文站语义相同。

## 1. 名词与计价口径（先看这一节，后面都靠它）

### 1.1 Credit 是什么

- 站内**余额、消费、Key 额度、分组限额**统一用 **Credit** 计价。
- 充值比例固定：**¥1 = 1 Credit**。国模的 CNY 源价和外模的 USD 源价，**数字直接等值映射**成基础 Credit 单价，**不做汇率换算**（例如源价 2 → 基础价 2 Credit）。
- 真实支付仍然是 **CNY（人民币）**；源价格保留原币种（CNY / USD）。

### 1.2 一条请求的账单是怎么算出来的

`
消费 Credit = 实际服务分组的有效倍率 × Σ(基础 Credit 单价_i × 归一化用量_i)
`

- **基础单价**：模型在价表里的基础 Credit 单价（按 1M tokens 或按次等计量单位）。
- **倍率**：分组倍率（可含峰谷倍率、视频独立倍率等）。**以实际服务的分组为准**，不是你看板时选的分组。
- **多项分别计算再相加**（输入 / 输出 / 缓存 / 媒体时长等），缓存不会被重复计算。

### 1.3 锁价：同一次请求不会中途变价

请求开始的那一刻锁定：请求开始时间、价格版本、基础单价、实际服务分组与该时刻的倍率。

- 请求执行期间管理员改价、改倍率，**不影响已经在跑的请求**。
- 内部重试不会重新取价。
- 账单详情里能看到这份"锁价快照"。

### 1.4 缺价不是 0 元

模型没有有效价格时，平台**在请求上游之前就拒绝**（错误：pricing_unavailable），不会按零成本放行、也不会回落成 GPT 兜底价。

- 显式配置为 0 元的模型是另一回事：那是"免费"，按正常价结算为 0。
- **对外含义**：`pricing_unavailable` 是**站点侧的价格配置问题**，不是你的 Key、余额或参数问题，你这边不需要做任何操作。站长可以在管理端的**「缺价清单」**（列出哪些模型价格不完整、缺哪一项）和**「价格总表」**（汇总渠道与分组规则里出现过的模型及其单价，只读）里核对。站内「帮助」页也写了这一节。
- **反过来说：不是所有"没配价"的模型都会报错**。平台对**部分模型**内置了该模型**自身的官方价**（官方内置价），命中时**按该官方价正常计费**、不报错。官方内置价**不是 0 元价**，也**不是"拿别的模型的价格顶替"**。
  所以准确的说法是：**既没有站长配的价、也没有官方内置价的模型**才会在转发上游前被拒（HTTP 503，错误码 `pricing_unavailable`）。
- **给你的判断方法**：某个模型能正常用并且有扣费 → 说明它要么有站长配的价、要么有官方内置价；某个模型直接报 `pricing_unavailable` → 说明它**两者都没有**，站长需要去配价。这一条对"为什么这个模型能调、那个不能"是最直接的解释。

### 1.5 实际服务分组与故障转移

平台按你的 Key 上配置的"普通分组尝试顺序"调度：

- 先在当前分组内找可用账号；该分组内候选耗尽（账号失效 / 限流 / 满载 / 站点侧故障）才尝试下一个分组。
- 用户侧错误（Key 无效、余额不足、参数错误、模型名无效、内容审核拒绝）**不会**触发换号换组。
- 账单里会记录**实际服务分组**和**故障转移**标识：正常是"无故障转移"；发生转移会标注转移原因与尝试次数。

### 1.6 峰谷时段：官方价格自动判定

DeepSeek 官方价格自带峰谷时段，平台按官方口径**自动判定**当前是峰价还是谷价，你不需要手动切换。

- **判定时区**固定为 **Asia/Shanghai**。
- **峰价窗口**：工作日（不含法定节假日）的 **09:00-12:00** 与 **14:00-18:00**；其余时间都是谷价。
- **法定节假日日历优先**：已维护的节假日按谷价计费；周末也按谷价，**包括调休需要上班的周末**。
- **生效倍率**：峰价按 **2 倍**计价，谷价按 **1 倍**计价。
- **在哪里看**：分组徽标上会显示当前是峰价还是谷价以及生效倍率（在「API 密钥」页的分组链、以及「订阅」页的分组卡上）。徽标**只反映分组的当前状态，不参与计费**，计费口径以后端价格表为准。
- **分组自定义优先**：如果管理员在分组表单里给这个分组配了高峰时段，以**分组配置的窗口和倍率为准**；没配置时才回落到 DeepSeek 官方时段。
- **同样遵循锁价**：请求开始那一刻的峰谷状态决定这次请求的计价口径，跨时段不会改价。
- **适用范围**：峰谷口径只作用在走 DeepSeek 官方价卡的模型与分组上；其它平台分组不适用，会显示为"不适用"。
- **年度兜底**：如果某个年份既没有维护节假日日历、也没有内置年度表覆盖，平台会停用这一年的官方峰谷加价（按谷价计），不会按工作日峰价收费。
- **别和「分组高峰时段」搞混**：站里还有**另一套**机制——站长可以给某个分组单独配「高峰时段」（自己的营业时间与倍率）。那是你和站长之间约定的**分组级**口径，与 DeepSeek 官方峰谷**互不相干**；分组配了自定义窗口时以分组配置为准，没配才回落到官方判定。两者在界面上是**分开的**，不要当成同一个开关。
- **能看到下一档的切换时间**：分组徽标旁会显示**下一档什么时候切换**（按平台时区显示）。它和徽标的"峰/谷"来自**同一次判定**（同一份官方日历、同一套规则），所以两个信息是自洽的。它是**当前日历下的推算**，不是承诺——节假日日历临时调整时以**实际扣费**为准。你看到徽标是"峰"，就按当时那一档理解。

## 2. 第一次使用

1. **注册并登录**本站。
2. **充值**（见第 4 节）。没有余额时 API 会返回余额不足。
3. **创建 API 密钥**（侧栏「API 密钥」→ 创建密钥）：
   - 选好普通分组（可多选，见第 3 节）。
   - 如需高可用兜底，**主动开启**（见第 3.2 节）。
   - 复制 Key。密钥只在创建时完整展示，注意保管。
4. **调用**：在「API 密钥」页复制默认端点或自定义端点，按 OpenAI 兼容协议调用：

       curl https://<你的站点域名>/v1/chat/completions \
         -H "Authorization: Bearer <你的 Key>" \
         -H "Content-Type: application/json" \
         -d '{"model":"gpt-4.1-mini","messages":[{"role":"user","content":"你好"}]}'

5. **回来看账**：「使用记录」里可以看到每条请求的实际分组、锁定单价/倍率、用量明细和最终 Credit。

## 3. 密钥的分组顺序与高可用兜底

（页面：侧栏「API 密钥」→ 创建/编辑密钥 → 「编辑普通分组顺序」）

### 3.1 普通分组尝试顺序

界面文案：

> **普通分组尝试顺序** —— 按顺序优先使用，当前组内候选耗尽后才尝试下一组；按实际服务组的有效倍率计费。

- 列表项可**上移 / 下移 / 移除**；未绑定时显示「未绑定普通分组」。
- 通用公开标准组始终可用；专属组仍需授权或订阅。
- **顺序即优先级**：把最想用、最稳定的分组放在最上面。
- 老的单分组 Key 会自动视为"长度为 1 的顺序列表"，行为不变。

### 3.2 高可用兜底分组（需要你主动开启）

界面文案：

> **高可用兜底分组** —— 普通分组全部不可用时，按顺序尝试你已开启的兜底分组；按实际服务分组的倍率计费。倍率由管理员设置。

- 默认**关闭**，需要你点「开启兜底」；该入口**只在编辑已有 Key 时出现**（新建 Key 的表单里没有），所以要先创建 Key 再回来开启。
- 兜底分组是**额外的稳定性能力**，不是默认链路的一部分：
  - 管理员配置了可用兜底组你才会看到「开启兜底」按钮；
  - 专属分组需要先有访问授权才能开启（提示「该分组为专属分组，需先获得访问授权才能开启兜底」）；
  - 分组模型范围与本 Key 不匹配时不可开启。
- 开启后仍然按**实际服务分组**计费（兜底组倍率可能更高），使用记录会显示故障转移标识。

### 3.3 分组限流

每个分组可以配置请求速率限制（QPS）和用户并发限制；超出时请求会被拒绝或排队，属正常限流行为，不是故障。

## 4. 充值与兑换：站内目前有两条链路，状态不同

> **先看清入口**：
> - **「充值/订阅」**（/purchase）：平台自建支付，**当前可用**，支付成功即到账。
> - **「充值中心」**（/shop）：白标商品中心（商品 → 支付 → 卡密 → 兑换），**当前尚未开通**。未配置时进入会看到：「充值服务尚未开通 / 站长尚未完成充值服务的配置，请稍后再试或联系站长。」

### 4.1 当前可用：充值/订阅（自建支付）

（页面：侧栏「充值/订阅」/purchase、「我的订单」/orders）

1. 选套餐下单，选择支付方式（以页面实际列出的渠道为准，如支付宝、微信、Stripe、EasyPay、Airwallex，取决于站点开通情况）。
2. 支付方式可能跳转到支付页面，或显示二维码（扫码支付）。
3. 支付完成后进入结果页，页面会**自动轮询后端订单状态**判定结果（约每 2 秒一次，最多 15 次左右）。
4. 「我的订单」（/orders）可按状态筛选（待支付 / 已支付 / 充值中 / 已完成 / 已过期 / 已取消 / 失败 / 退款中 / 已退款 等），未支付订单可「取消订单」，已完成订单可「申请退款」（取决于渠道是否支持退款）。
   - **退款口径（重要）**：退款**受理后额度先不退回**——系统在受理时就已经把要退的金额从你的余额里扣掉了，并保持"已扣减"状态，直到渠道退款**成功（额度退回）**或**失败（收口）**为止。所以**看到余额先少了是正常的**，不是重复扣费；这段时间里也**不要重复发起退款**（会重复扣减并向支付渠道重复退款）。
5. 断网或刷新后可找回：结果页会保留本次支付的恢复信息，重进 /payment/result 会用订单号或恢复凭据回查；也可以在「我的订单」里找。

### 4.2 「充值中心」/shop：设计形态与当前限制

**设计形态**（等站点开通后才会真正可用）：

- 商品卡展示：商品名称、描述、**可得 Credit**、库存、¥ 售价、划线价、「立即购买」；目录四态：加载中 / 未配置 / 同步失败（**保留商品展示但暂停购买**）/ 空。
- 支付指引两种：**二维码**（本站渲染）或**跳转支付渠道**；支付状态完全由后端判定，页面不会仅凭前端结果认定支付成功。
- 订单状态四种：待支付 / **已支付 / 待交付** / **已支付 / 交付异常** / **已交付**。
- 交付异常时页面原文：

  > 支付已完成，但卡密暂未获取成功
  > 请联系站长处理；本站订单号：{orderNo}。你也可以点击「查询最新状态」重试。

- 卡密仅在「已交付」且订单属于你本人时才展示明文，可一键「复制卡密」。

**当前限制**（避免你按不可用路径操作）：

1. 站点未配置该服务时，页面直接提示「充值服务尚未开通」。
2. 支付形式为"跳转支付渠道"时，**不会自动跳转**（只显示提示文字）。
3. 刷新或断网后，「充值中心」页的**「我的订单」列表**仍可查历史订单并主动回查；但本地**只保存最近一次订单号**，清掉浏览器数据后请凭提示里的本站订单号找站长。
4. 「去兑换」目前只对**本站兑换码**有效；上游发放的卡密尚未接入本站兑换表。

### 4.3 兑换（/redeem）：只对本站兑换码有效

- 输入兑换码 → 兑换 → 成功卡显示「已添加: {值} Credit」（余额类）/「已添加: {n} 并发请求」/「订阅已分配 - {分组} ({n} 天)」，并给出「新余额: {值} Credit」。
- 兑换码**区分大小写**、**只能兑换一次**；可用于加余额、加并发数或试用权限。
- 失败时页面**会区分原因**：「该兑换码已被使用」/「兑换码不存在」/「兑换码已过期」/「兑换码无效」。若你确信码没错却失败，把兑换码和提示发给站长核对（重复兑换不会重复加额度）。

### 4.4 金额单位有两个口径（别被 $ 误导）

- 站内账本单位是 **Credit**，界面标签统一带「（Credit）」：**余额**、仪表盘消费与平台配额、**密钥额度**与 5 小时/1 日/7 日窗口限额、兑换页、充值与订单页的到账金额与赠送额度、订阅分组日/周/月限额、侧栏订阅进度小卡、批量生图任务的费用，都用 Credit。
- **仍显示源币种 $ 的地方**：**模型广场**价格表展示的是源币种价目（美元，不换汇），不是账户余额里的 Credit；实际扣减以「使用记录」中的 Credit 为准。
- 充值页与订单页还会标注「当前倍率：1 {currency} = {usd} USD」；这是**充值倍率**说明，和"1 元 = 1 Credit"不是同一口径。
- 「兑换」页与「充值中心」现在会明确提示 **「¥1 可得 1 Credit（不换汇）」**，实际比例以站点配置为准。

## 5. 使用记录怎么读

（页面：侧栏「使用记录」/usage；管理员视角在「管理后台 → 使用记录」/admin/usage）

一条记录里你能看到：

| 字段 | 含义 |
|---|---|
| 记录消费（Credit） | 这条请求实际扣掉的 Credit |
| 快照最终消费 | 锁价快照里的最终消费，用于复核 |
| 基础单价（Credit）/ 已存小计（Credit） | 各计费项的基础价与小计 |
| 实际服务分组 | 真正服务这次请求的分组（可能不是你排第一的那个） |
| 故障转移 | "无故障转移"或转移原因 + 尝试次数 |
| 用量明细 | 输入 / 输出 / 缓存 token，或图片张数、视频秒数、实时语音时长 |
| 定价快照 | 源价格（CNY/USD 与计量单位）、基础 Credit 单价、分组倍率 |

注意：**官方源价的金额在用户侧不展示**，快照里只有换算成 Credit 的基础单价和币种/来源元数据；"源价 × 倍率 = 实扣"这条链的源价一端要去模型广场或问站长。

**如果"记录消费"和"快照最终消费"不一致**，页面会提示：

> 记录与锁价快照的实际分组或消费不一致，以下保留两份已存数据供核对；页面不会改账或自动纠正。

这种情况不要重复提交请求，把该条记录的 request_id 和时间点交给站长核对。

### 5.1 视频任务页

（页面：侧栏「视频任务」/video-tasks）

可以查**你自己提交的视频生成任务**：

| 字段 | 含义 |
|---|---|
| 任务号 | 站内任务标识，找站长核对时提供这个号 |
| 状态 | 处理中 / 已完成 / 失败 |
| 模型与平台 | 这次任务实际用的模型和所在平台 |
| 计费模式 | 按量（Token）/ 按次 / 按秒 |
| 创建时间 | 任务创建的时刻 |
| 结算时间 | 任务结算完成的时刻，未结算时不显示 |
| 失败原因 | 失败任务显示原因，成功或处理中为空 |

- **计费模式取自任务创建时的计费快照**：创建那一刻按分组与模型匹配到的计费口径就固定下来，之后改价**不改**这条任务的计费模式。
- 列表按创建时间倒序，一页 20 条（上限 50），有更多时点「加载更多」按游标翻页。
- 只返回**你自己的**任务，不包含上游任务号等内部字段。
- 该页只展示任务与计费信息，**不提供成片下载**；视频消费仍以「使用记录」里的计费口径为准。

## 6. 图片、视频与实时语音怎么计费

- **图片**：按张与规格计费，部分模型支持独立倍率与批量生图（侧栏「批量生图」）。
- **视频**：分**三种**模式，**按模型 × 分组**配置，一种组合只配一种：
  - **按量（Token）**：按每百万 token 单价 × 实际 token 用量计费；
  - **按秒**：费用 = 每秒价格 × 时长（平台侧 1–15 秒，未指定默认 8 秒），可按 480p / 720p / 1080p 分档；
  - **按次**：按请求次数计费。
  - 视频可能使用**独立倍率**（与文本倍率分开）。
- **实时语音（Live / Realtime）**：**按会话时长计费**，单价来自分组上的语音/Realtime 每分钟单价配置。**注意现状**：该单价现在在管理后台**对所有平台的分组都可配置**（分组表单的「语音 / Realtime 显式定价」区块）；分组没有配置单价时，本次会话会按**未计费**落库（后台会有告警）——遇到 Live 消费为 0 时，先找站长确认该分组是否配了单价。用户侧**分组徽标**会显示 Live 徽标与 Realtime 每分钟单价（标注为源价、非最终扣费），「使用记录」的明细里能看到 Live 会话时长与计费口径。
- 视频/图片任务在提交时同样遵循"提交即锁价"。
- **视频任务有独立的用户侧入口**（侧栏「视频任务」/video-tasks，见第 5.1 节）；该页只展示任务与计费信息，**不提供成片下载**。图片有「批量生图助手」入口，费用按 Credit 显示。
- 面向用户的图片/视频计费口径说明已经上线：站内「帮助」页（/help）的「图片、视频与实时语音计费现状」一节（按次/按张/按秒、分辨率档位、是否叠加分组倍率等）。

## 7. 常见问题

**Q：为什么这次比上次贵？**
A：最常见是**实际服务分组变了**（发生了故障转移，兜底组倍率更高）。在使用记录里对比"实际服务分组"和"倍率"即可确认。

**Q：请求报 pricing_unavailable / 缺价？**
A：模型当前没有有效价格，平台按"缺价不放行"原则在请求上游前拒绝。这是平台侧的价格配置问题，请把模型名和时间点反馈给站长；站长可在管理端的「缺价清单」与「价格总表」里核对。

**Q：请求被限流（429）？**
A：分组的 QPS 或你的并发上限触顶。可以在「API 密钥」页看当前并发，必要时换分组或联系站长提并发。

**Q：余额没到账？**
A：分两种情况。①「充值/订阅」自建支付：**支付成功即到账**，若未到账请带订单号找站长核对；②「充值中心」白标商品：支付成功后**不会自动到账**，需要复制卡密到「兑换」页兑换，**但该入口当前尚未开通**，页面会直接提示"充值服务尚未开通"。

**Q：卡密在「兑换」页提示失败？**
A：「兑换」页目前只认**本站发放的兑换码**。如果你的卡密来自外部渠道（白标商品中心的卡密尚未接入），本站暂时无法兑换，请把卡密与本站订单号发给站长处理。另外该页现在**会区分原因**：「该兑换码已被使用」/「兑换码不存在」/「兑换码已过期」/「兑换码无效」。

**Q：扣费了但没查到记录？**
A：先在「使用记录」按时间窗和 Key 过滤；图片/视频任务是异步任务，可能需要等任务完成或轮询任务状态。

**Q：能退能改价吗？**
A：充值得到的 Credit 是站内额度；价格与倍率由平台维护，平台不会随汇率自动调整售价。历史账务纠错需要站长按对账流程处理。
另外，**申请退款受理后额度先不退回**（余额会先扣掉），直到支付渠道退款成功或失败收口才定下来——详见 4.1。

**Q：用 GPT-5.5 报 404 model_not_found，是被全面下架了吗？**
A：**不是全面下架。**准确口径是：**自 2026-10-14 19:00 UTC 起，ChatGPT 登录方式（OAuth / SetupToken / 凭据影子账号）的上游不再提供 GPT-5.5**；**API Key 上游不受影响**，仍然可以正常调用。返回 404 model_not_found 的典型情形是：你这个 Key 所在分组**只挂了 ChatGPT 订阅账号**。如果你走的是 API Key 渠道仍然报错，请把模型名、时间点和你的 Key 尾号交给站长，核对分组里挂的是哪类账号。

**Q：怎么给站长提供排查信息？**
A：提供 ① 本站订单号（充值问题）② request_id（或时间窗 + 模型名 + Key 尾号）③ 错误码与提示原文（调用问题）。不要提供完整 Key。
