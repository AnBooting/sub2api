## TS-02 亲和调度与故障转移（PRD-02）

现状锚点
- 两套调度实现共用 ConcurrencyService（architecture/02-scheduling.md）。

- 调度读快照，outbox 刷新有秒级延迟（config.go:2569-2571）。
- Key 只有单个 group_id（ent/schema/api_key.go:44）。

3. 失败分类器（C-5）放在转发结果出口，一处实现，两套调度共用。
4. 外层组循环：组内换号耗尽 → 下一普通组 → TS-04 兜底；总尝试上限 + 总时间预算。
5. 策略三档（C-4）映射到现有粘性/等待参数，作为代码常量。
6. FE：Key 页多选排序；使用记录显示实际组/转移标识；管理页策略选择。

数据变更：api_key_group_links 表（C-3）、group.scheduling_strategy 字段、usage_logs 字段（同 TS-01 迁移）。

测试：AC-B2 组内→组间→恢复回切；本站参数/鉴权/余额前置错误上游0次，上游审核/业务拒绝至多1次且不二发；累计首字节/不确定执行不重试；并发槽位归零；陈旧normal编辑/HA关闭并发409不得复活HA；A/B订阅与余额身份隔离。

Q-2/Q-3/K-2 已收口，见90；生产跨组仍依赖TS-01不可变价表/候选倍率与实际组一次结算，不能用cloneKey代替。16次/600秒为用户确认新初值，不是线上压测结论。
## TS-03 云猫白标充值与卡密交付（PRD-03）

## TS-05 DeepSeek 峰谷计价（PRD-05）

评审前锚点：USD 默认价卡的峰谷写死在 `deepseekPeakMultiplierAt`，CNY 价卡使用 `schedule{timezone, windows[weekdays, hours]}`，两者都未处理法定节假日。当前本地修复：`deepseek_calendar.go` 共用北京时间日历；USD 使用 `deepseekPeakMultiplierWithCalendar`，CNY 在选择 schedule 前排除北京时间节假日及周末。内置 2026 年官方放假日期，管理员通过 `PUT /api/v1/admin/channels/pricing/settings` 的年度 `deepseek_holidays` 或兼容 `/pricing/holidays` 列表接口更新同一日历，统一持久化至 `model_pricing_controls`；旧 `deepseek.holidays` 仅在新字段缺失时读取迁移；自定义表缺取价年份时回落内置表，两者均缺年则禁用高峰加价。状态接口暴露覆盖年份与错误，启动、同步和现有周期任务检查当前年份并复用 Ops 告警，查价不读取告警配置或发送邮件。分组/渠道自定义单价保留运营者语义（PRD-05 §2.11），不继承官方峰谷；其留空继承的 USD 字段通过 `PricingInput.PricingAt` 或请求上下文冻结时刻取价。

改动点
1. 官方政策已取证（K-8 已决）：判定顺序 法定节假日→空闲；周六/周日→空闲（补班忽略）；周一至周五按时段。新增法定节假日集合（settings `deepseek.holidays`，按年维护，管理员可改；缺当年数据按上述回落规则处理，无法覆盖时只用谷价并由后台告警）。USD 与 CNY schedule 共用同一判定；非 DeepSeek CNY 查价不读取日历。
2. 结算链路按请求开始时刻取价并回写 `NativePricingAt`。Anthropic/Chat/Responses/Gemini/SystemOne 入口调用 GatewayService 的 `WithGatewayTokenRequestPricing`，OpenAI 入口调用 `WithOpenAIRequestPricingContext`，同时捕获不可变日历快照；WebSocket 每个 turn 重新捕获。预留、异步用量记录及最终重新解析价卡均沿用该快照，编辑假日不改变在途请求的 USD/CNY 峰谷判断。develop 的锁价入口另使用完整价表、分组、映射 bundle；日历也进入该 bundle 及价格版本。旧路径仅冻结日历和时点，仍不能宣称全部入口满足完整锁价条款。
3. `billing_context_schedule.go:121` 用 `timezone.Now()` 生成上下文分档价，`channel_available.go:129` 用 `time.Now()`：确认它们只用于展示，不进入结算；若进入结算则改为请求开始时间。
4. 加载校验已检查时区、星期、时刻格式（pricing_native_cny.go:110-134），**未检查窗口重叠/空档**，需补。
5. 快照写 `period`（C-1）。

测试：PRD-05 AC-B7 日期用例；边界时刻 [start, end) 各取一次；请求在峰时开始、谷时结束仍按峰价；服务器时区设为 UTC 结果不变。

阻塞：无（节假日集合需每年初录入）。

## TS-06 图片回迁与视频计费（PRD-06）

- 视频：Grok 按时长计费（grok_media.go:68、138）；Seedance 按上游 `usage.completion_tokens` 计费（seedance.go:150），仅客户端查询到终态才结算（docs/seedance-api.md:40-41），任务只存 Redis 24 小时。
- 未知视频模型回落图片价（billing_service.go:2377），违背缺价拒绝。

改动点
1. 图片：先拿迁移清单（Q-7），逐条比对现有端点，差异只补适配；不重设计图片计价。
2. 视频定价配置：模型×分组 → `{mode, base_credit_price}`，唯一约束保证一种模式；缺配置在提交前拒绝（`pricing_unavailable`）并移除图片价回落。

4. 服务端推进：后台按配置间隔查询未终态任务；终态迁移条件更新，结算一次（S-4）。
5. 余额：提交前按「单价 × 倍率 × 请求时长上限」校验；是否复用现有预扣能力在实现前核实。
6. Seedance 改为按次/按秒售卖（K-4 已决），单价待 Q-8。

测试：AC-B3 两组两模式（6 与 10 Credits）；客户端从不查询仍结算；重复回调只结算一次；他人任务 ID 查询 403/404；缺价不发上游。

阻塞：Q-7（图片）、Q-8（视频）。依赖 TS-01 快照、TS-02 分类。
