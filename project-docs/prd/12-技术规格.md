## TS-01 Credit 计价与价格同步（PRD-01）

现状锚点
- Credit 映射与原生 CNY 已落地：commit 11109acd、service/pricing_native_cny.go、migrations/243_native_currency_pricing.sql。
- 价格源：USD `pricing.remote_url`（config.go:2348），CNY `pricing.native_cny_url` + 补齐源（config.go:2353-2354），CNY 默认关闭（config.go:2352）。
- 同步周期只读配置文件 `pricing.update_interval_hours`（config.go:2357，用于 pricing_service.go:444/490）。
- 快照 v1：service/pricing_snapshot.go:7，无实际服务组、无价版本。

改动点
1. 周期：settings 覆盖配置文件默认值，修改后重排下一次同步（K-6）。
2. 校验 + 原子替换 + LKGP + 同步状态（C-2）；状态变化时发 `ops.alert` 邮件，持续失败不重复。
3. 快照升级 v2（C-1），写入 `served_group_id` 与开始时点倍率。
4. 缺价拒绝（K-5 已决）：国模、外模均在调用上游前返回 `pricing_unavailable`；移除外模零价放行（openai_gateway_usage.go:259-272），不设开关。显式零价正常结算为 0。
5. FE：Credit 文案按字段替换；价格页源价/基础价/倍率/售价分列；同步周期与状态。

数据变更：usage_logs 增 served_group_id、requested_group_id、failover、attempt_count（C-6，与 TS-02 同一迁移）；同步状态存 settings 或内存+日志（选其一，在实现时定，不新建表优先）。

测试：AC-B1 验算（CNY 2→1.2、USD 2→8）单测；币种反转/单位异常不覆盖；LKGP 下请求仍可结算；上线前后余额导出 diff 为 0。

阻塞：Q-1 混合币种分组、Q-9 旧记录展示。上线前需按 WARN 日志盘点线上外模缺价清单并补价，否则这些模型会被拒绝。

## TS-02 亲和调度与故障转移（PRD-02）

现状锚点
- 两套调度实现共用 ConcurrencyService（architecture/02-scheduling.md）。
- 负载率分母取 `EffectiveLoadFactor()`（account.go:169；gateway_scheduling.go:441/712），`load_factor` 与 `concurrency` 不一致时出现「贴顶」或「被过滤」（gateway_scheduling.go:453/730）——账号负载不均的首要嫌疑。
- 调度读快照，outbox 刷新有秒级延迟（config.go:2569-2571）。
- Key 只有单个 group_id（ent/schema/api_key.go:44）。

改动点
1. 先修负载率分母：并发硬上限与负载评分统一口径，补回归测试；用压测确认后再判断是否需要其他调整。
2. Key 分组链（C-3），鉴权缓存带上链。
3. 失败分类器（C-5）放在转发结果出口，一处实现，两套调度共用。
4. 外层组循环：组内换号耗尽 → 下一普通组 → TS-04 兜底；总尝试上限 + 总时间预算。
5. 策略三档（C-4）映射到现有粘性/等待参数，作为代码常量。
6. FE：Key 页多选排序；使用记录显示实际组/转移标识；管理页策略选择。

数据变更：api_key_group_links 表（C-3）、group.scheduling_strategy 字段、usage_logs 字段（同 TS-01 迁移）。

测试：AC-B2 组内→组间→恢复回切；AC-B3 四类用户错误上游调用次数 = 1；流式首字节后不重试；并发压测槽位归零。

阻塞：Q-2 新 Key 默认组、Q-3 尝试上限基线、K-2 访问校验口径。
## TS-03 云猫白标充值与卡密交付（PRD-03）

现状锚点
- 本站已有完整支付系统（5 个 provider、三层幂等）与 `POST /api/v1/admin/redeem-codes/create-and-redeem`（routes/admin.go:548），见 architecture/04-payment-fallback.md。
- 云猫接口、签名、测试店铺：**未核实**（Q-4）。

改动点（接口资料到位后再细化，先定边界）
1. 服务端适配层 `yunmao` 包：商品同步、下单、查单、取卡密；凭据只走服务端配置（S-5）。
2. 映射表（逻辑名 `yunmao_orders`）：本站订单号、user_id、云猫订单号（唯一）、商品快照、展示状态、卡密（加密存储）、最近查询时间。
3. 商品快照 + 同步状态；同步失败时服务端拒绝新下单（`product_sync_unavailable`），已有订单查询不受影响。
4. 展示状态只做映射：待支付 / 已支付 / 交付异常 / 已交付；支付结果只认云猫回调验签或服务端查单。
5. FE：充值页改商品中心；订单详情复制卡密并跳转现有兑换入口；全部文案与 URL 去品牌。

数据变更：yunmao_orders、商品快照表（或 settings JSON，商品量小时优先后者）。

测试：重复回调/重复点击只有一条映射；卡密只对本人可见；前端源码与网络请求中搜不到云猫域名；同步失败暂停购买、恢复后可买。

阻塞：Q-4（整节阻塞，资料不到不开工）、Q-5 现有支付入口去留、K-7。

## TS-05 DeepSeek 峰谷计价（PRD-05）

现状锚点：USD 默认价卡的峰谷写死在 `deepseekPeakMultiplierAt`（billing_service.go:309-320，UTC 01–04/06–10 即北京 09–12/14–18，周末全天空闲，**无法定节假日**），在 billing_service.go:1612-1619 乘 2；CNY 价卡 `schedule{timezone, windows[weekdays, hour_ranges]}`，按请求时刻选价（pricing_native_cny.go:39-46、271-303），区间 `[start,end)`、支持跨午夜。

改动点
1. 官方政策已取证（K-8 已决）：判定顺序 法定节假日→空闲；周六/周日→空闲（补班忽略）；周一至周五按时段。新增法定节假日集合（settings `deepseek.holidays`，按年维护，管理员可改；缺当年数据时告警，仍按周一至周五时段计价，不猜假期）。`deepseekPeakMultiplierAt` 与 CNY schedule 共用同一判定。
2. 结算链路已按传入时刻取价并回写 `NativePricingAt`（pricing_native_cny.go:450-461、477-482）；已核实：Anthropic/Chat/Responses/Gemini/SystemOne 入口经 `WithGatewayTokenRequestPricing`（gateway_request_pricing.go:17-29）在请求入口冻结时刻；OpenAI 入口由 handler 传 `PricingAt`，空值才回落 `timezone.Now()`（openai_gateway_usage.go:128-133）。改动：回落路径加 WARN 并补测试，保证取价 = 发起时刻。
3. `billing_context_schedule.go:121` 用 `timezone.Now()` 生成上下文分档价，`channel_available.go:129` 用 `time.Now()`：确认它们只用于展示，不进入结算；若进入结算则改为请求开始时间。
4. 加载校验已检查时区、星期、时刻格式（pricing_native_cny.go:110-134），**未检查窗口重叠/空档**，需补。
5. 快照写 `period`（C-1）。

测试：PRD-05 AC-B7 日期用例；边界时刻 [start, end) 各取一次；请求在峰时开始、谷时结束仍按峰价；服务器时区设为 UTC 结果不变。

阻塞：无（节假日集合需每年初录入）。

## TS-06 图片回迁与视频计费（PRD-06）

现状锚点
- 图片：`/v1/images/generations`、`/async`、批量 `/images/batches`（routes/gateway.go:253-261）。
- 视频：Grok 按时长计费（grok_media.go:68、138）；Seedance 按上游 `usage.completion_tokens` 计费（seedance.go:150），仅客户端查询到终态才结算（docs/seedance-api.md:40-41），任务只存 Redis 24 小时。
- 未知视频模型回落图片价（billing_service.go:2377），违背缺价拒绝。

改动点
1. 图片：先拿迁移清单（Q-7），逐条比对现有端点，差异只补适配；不重设计图片计价。
2. 视频定价配置：模型×分组 → `{mode, base_credit_price}`，唯一约束保证一种模式；缺配置在提交前拒绝（`pricing_unavailable`）并移除图片价回落。
3. 本地任务表（逻辑名 `video_tasks`）：本站任务 ID、user_id、api_key_id、served_group_id、上游账号与任务 ID、锁价快照、状态、结算标记。
4. 服务端推进：后台按配置间隔查询未终态任务；终态迁移条件更新，结算一次（S-4）。
5. 余额：提交前按「单价 × 倍率 × 请求时长上限」校验；是否复用现有预扣能力在实现前核实。
6. Seedance 改为按次/按秒售卖（K-4 已决），单价待 Q-8。

测试：AC-B3 两组两模式（6 与 10 Credits）；客户端从不查询仍结算；重复回调只结算一次；他人任务 ID 查询 403/404；缺价不发上游。

阻塞：Q-7（图片）、Q-8（视频）。依赖 TS-01 快照、TS-02 分类。
