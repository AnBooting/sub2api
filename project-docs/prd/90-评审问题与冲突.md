## K 冲突（PRD 前提与源码不一致）

| # | PRD 原文 | 源码事实 | 影响 | 建议 | 决策 |
|---|---|---|---|---|---|
| K-1 | 国模价格「使用 LiteLLM 提供的 CNY 价格数据」（00 §2、01、05、06） | 国模 CNY 实际来自 basellm llm-metadata，补齐源 llm-prices-cn（config.go:2353-2354）；外模 USD 来自 Wei-Shaw/model-price-repo 的 LiteLLM 格式文件（config.go:2348）。LiteLLM 本身没有 CNY 价格数据 | 若坚持「LiteLLM CNY」，没有可直接对接的数据源 | PRD 改为「国模使用现有 CNY 价格源（basellm + 补齐源），外模沿用现有 USD 源」，口径不变：不分别抓厂商官方价 | |
| K-2 | 「当前系统不存在用户分组访问限制」（02 §1、04 §1） | 存在专属分组与授权：`is_exclusive` + `user_allowed_groups` + 订阅分组，Key 绑组时校验（service/api_key_service.go:480-488、1092） | 若照写「不校验」，等于给所有用户开放专属/订阅组 | 改为「本期不新增访问限制；沿用现有专属/订阅分组校验，普通组链和兜底组都受它约束」。兜底组需由管理员保证非专属，或用户已有权限 | |
| K-3 | 高可用兜底为新能力（04） | 已有 `fallback_group_id`（非 Claude Code 客户端降级）与 `fallback_group_id_on_invalid_request`（仅 prompt too long）（ent/schema/group.go:202-206） | 名称接近，容易误复用 | 兜底不复用这两个字段，用 C-3 role=ha；旧字段保持原语义 | |
| K-4 | 视频首期按次/按秒（06） | 已有 Grok 视频（按秒×时长×数量）与 Seedance（按上游 completion_tokens 计费）；无本地任务表，仅客户端轮询到终态才结算；未知视频模型回落 2K 图片价（billing_service.go:2377） | 现状同时违背「客户端不查询也要结算」和「缺价不放行」 | TS-06 新增视频任务表与服务端推进；Seedance 若按 token 计价，属于「Provider 必需的额外维度」，需确认售价模式 | |
| K-5 | 「外模零成本放行开关不属于本期新增需求，未确认的缺价策略不纳入冻结规则」（01 §3），同时要求「没有有效价格时不以零价冒充正常定价」 | USD 外模缺价零成本放行（openai_gateway_usage.go:259-272）；ADR-010（07-decisions.md）已由用户确认「改为拒绝、开关默认关闭」 | PRD 与 ADR-010 范围不一致；默认配置下外模缺价仍零价放行 | 以 PRD 为准：本期不做该开关，ADR-010 改为「推迟」；TS-01 只保证国模 fail-closed 与零价/缺价可区分。若甲方要纳入，按 ADR-010 单列任务 | |
| K-6 | 同步周期「优先复用 Pricing / Scheduler 配置」并在管理页可改（01 FE-06） | 周期是配置文件键 `pricing.update_interval_hours`（config.go:2357），非数据库设置，管理页不可改 | 需要补设置项与热更新 | TS-01 增加 settings 覆盖，配置文件值作默认 | |
| K-7 | 云猫「交付卡密，不自动兑换」（03） | 已有完整支付系统（5 个 provider）与 `create-and-redeem` 原子建码兑换（routes/admin.go:548） | 本站支付系统与云猫并存，充值入口要选一个 | 充值页切换为云猫商品中心；本站自有支付入口是否下线需决策 | |
| K-8 | DeepSeek 按官方峰谷政策（05） | 实现已支持数据驱动的 schedule（pricing_native_cny.go:271-303）。DeepSeek 当前官方是否仍有峰谷优惠**未核实**，需以官网定价页为准 | 若已取消，PRD-05 只剩「不误用谷价」的验证 | 阶段 A 先取证官网定价页；无峰谷则 PRD-05 降为验证项 | |
