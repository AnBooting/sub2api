# PRD-05 DeepSeek 峰谷价格自动计费

版本：1.2｜日期：2026-10-10｜优先级：P0

## 1. 目标与范围

DeepSeek 价格金额使用 basellm 的 CNY 价格数据，峰谷时段、时区和政策规则按 DeepSeek 当前有效官方政策。同一分组按官方规则自动选择适用价格档，用户无需切换分组。请求开始锁价，跨时段及执行期间价格更新不改变本次消费。

采用同分组自动切价和请求开始锁价，依据见路线文档。实施前分别核实 basellm 中目标模型的 CNY 价格数据与 DeepSeek 官方时区、有效峰谷时段和政策。优先复用现有能力，仅补缺口；能配置解决的不开发，上游已有能力优先升级/移植。

## 2. 业务与计算规则

1. basellm 负责提供目标 DeepSeek 模型的人民币价格数据，CNY 数值映射同数 Credit，不换汇；DeepSeek 官方规则负责决定请求在什么时段采用哪档价格。本站不分别建设 DeepSeek 官方价格采集接口。
2. 时间判断使用官方规定的时区和日历规则，不能采用服务器本地时区作为隐含依据。跨午夜时段按真实官方边界处理，区间采用一致的起点包含、终点不包含语义，保证每一时间点只有一个有效价。
3. 请求开始时间采用 PRD-01 的本站接收并通过基础校验时点。按该时点锁定模型、时段、价版本及各计费项；流式持续、排队、内部换号/换组均不重新选择峰谷价。
4. `consumption_credit = actual_group_multiplier × Σ(locked_period_base_price_i × normalized_usage_i)`。输入、输出、缓存等有独立价格时分别计算，按 basellm CNY 价格数据对应的计量单位归一化。
5. 峰谷只改变模型基础价，不修改分组倍率，也不新建峰/谷分组作为本规则的替代。分组倍率遵循 PRD-01 的开始时点配置快照。
6. basellm 价格数据或 DeepSeek 官方峰谷政策变更后，按明确有效时间用于之后的新请求，已锁价请求仍用原版本，历史请求不回算。
7. 若官方对某模型已取消峰谷优惠，按当前有效官方政策选取适用的 basellm CNY 价格，不继续使用过期谷价。实施前核实数据与政策的对应关系。
8. 官方时段（2026-10-10 取证）：北京时间周一至周五 `[09:00,12:00)`、`[14:00,18:00)` 为高峰，其余为空闲；峰价 = 空闲价 × 2。日历判定顺序：中国法定节假日 → 全天空闲；否则周六/周日 → 全天空闲（**调休补班的周六/周日同样全天空闲，补班属性不参与判断**）；否则按上述时段。只维护「法定节假日集合」，不维护补班集合。依据：官方定价页文字「周一至周五」，以及 2026-09-20（周日补班）用户实际账单反馈为空闲价。文案用「空闲价/谷价」，不写「半价」。
9. 取价时刻为本站接收请求的发起时刻（同第 3 条），不是结算或响应结束时刻。
10. 同步周期、Last Known Good Price 保留及 Alert / Email 告警统一复用 PRD-01；同步异常不修改分组倍率，不另建告警或切价系统。
11. 峰谷政策仅适用于官方基础价。分组或渠道一旦配置自定义 Token 单价，视为运营者售价，不继承官方 CNY schedule，也不额外叠加 USD 官方峰谷倍率；自定义价的时段变化由其显式 `time_pricing` 控制。CNY 手工卡必须完整填写输入、输出、缓存读取和缓存写入价格，免费项显式为 0；缺项在请求前与结算入口均返回 `pricing_unavailable`。

### 评审修复落实（本地）

USD 与 CNY 官方价共用北京时间节假日日历 `deepseek.holidays`。未配置时内置 2026 年官方放假安排；后台「模型价格与额度计费」可编辑并持久化完整日期列表。网关请求入口捕获不可变日历快照，预留及异步最终结算（包括重新解析 CNY 价卡）沿用原快照，编辑日历只影响新请求；WebSocket 每个 turn 捕获自己的快照。此补丁冻结日历规则和取价时点，普通价表及分组配置的完整版本快照仍未实现，不能据此宣称已完整满足第 3 条及 BE-03。非空保存必须包含当前北京年份，空数组恢复内置日历；损坏的持久化内容回落默认并告警。自定义表缺少年份时回落内置表，两者均缺年则禁用高峰加价；状态接口及后台暴露覆盖年份与错误。启动、同步及现有周期任务检查当前年份并发送 Ops P1 告警，计费查价只读日历，非 DeepSeek CNY 查价不做日历判定。后续年份仍需运营者维护。日历更新使用独立写入锁与读写锁，数据库写入不阻塞计费读取；更新受 step-up 验证，审计记录修改前后日期。同步失败复用 Ops 告警邮件的收件人、开关、严重级别、限流及模板；同一来源持续故障一小时内合并，确认成功同步后解除抑制，邮件仅含错误类别。告警配置读取失败或全部邮件投递失败会释放抑制占位，允许下一次后台检查重试。详见 `backend/internal/service/pricing_pr2_rereview_test.go`、`pricing_pr2_regression_test.go`、`pricing_review_test.go` 与 `pricing_sync_alerts_test.go`。

2026 年日期来源：[国务院办公厅关于2026年部分节假日安排的通知（国办发明电〔2025〕7号）](https://zwfw.gansu.gov.cn/huixian/zczx/tzgg/art/2025/art_715c16a75e4d4c289c295e77772c7274.html)。仅维护放假日期，不将周末补班改成峰价日。

## 3. FE 需求

| 编号 | 需求 |
|---|---|
| FE-01 | 价格管理分别展示 basellm 源 CNY 价、基础 Credit 价及 DeepSeek 官方峰谷时段/时区，明确价格数据来源、规则来源与有效时间 |
| FE-02 | 用户价格展示说明“按请求开始时段计价”，同组无需人工切换；预览价格不承诺尚未提交请求的最终锁价 |
| FE-03 | 消费详情展示本请求采用时段/价版本或等价证据、实际服务组、单价、用量与消费；不以当前时段覆盖历史详情 |
| FE-04 | basellm 价格同步异常或缺有效价时明确提示，不显示为免费或误标为同步成功 |

## 4. BE 需求

| 编号 | 需求 |
|---|---|
| BE-01 | 复用 PRD-01 的 basellm CNY 同步任务和价表，结合 DeepSeek 官方峰谷时段、时区及政策有效期选择价格档；不另建独立计费引擎或厂商价格采集系统 |
| BE-02 | 校验时段覆盖/冲突及模型映射，一次更新完整版本，不让请求读到半套峰谷价 |
| BE-03 | 按请求开始时间一次解析并锁定，重试沿用；记录足够复算的时段价格与实际组倍率 |
| BE-04 | 同步异常复用 PRD-01 的 Last Known Good Price + Alert / Email，继续使用最近有效规则并抑制高频重复通知；没有适用有效配置时在调用上游前拒绝 |
| BE-05 | 复用精度、使用量与单次结算；输入/缓存/输出分类不得重叠扣费 |

逻辑字段优先使用现有配置与 usage 记录；已具备上述能力时只补验证与展示。不要为按时间取价新增队列、定时改倍率任务或长期运行的切价进程。

| 类别 | 编号 | 场景与预期 |
|---|---|---|

| BE | AC-B6 | 同步失败不覆盖最近有效规则，继续按该规则服务并记录异常、通知管理员；同一持续故障不高频重复邮件 |

## 6. 依赖与实施前材料

依赖 PRD-01 的 basellm 国模 CNY 来源、锁价与账本，PRD-02 的重试沿用开始时点。需分别核实目标模型的 basellm 价格金额与 DeepSeek 官方有效峰谷政策，保留来源与采集时间；若没有有效峰谷政策，先如实记录再确认适用范围，不用旧截图或历史价作当前依据。

如 basellm 当前数据无法完整表达所需峰/谷两档价格，将其列为 DeepSeek 接入缺口，按现有 Sub/basellm 能力做最小补充；不得自行猜价，也不得因此重建全套厂商价格采集系统。
