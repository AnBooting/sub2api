# PRD-04 用户授权高可用兜底分组

版本：1.2｜日期：2026-10-10｜优先级：P1

## 1. 目标与范围

在普通分组链无法服务时，为用户提供可选的高可用渠道，同时使高倍率消费有明确授权。AWSB 是原需求中的兜底示例，不是所有请求的默认目标，也不证明其支持全部模型。

管理员配置不能替代用户主动开启，依据见路线文档。当前系统不存在用户分组访问限制，兜底不依赖独立分组访问权限。高可用兜底既是稳定性能力，也可作为向用户推荐更高质量分组的增值入口；是否开启始终由用户决定。优先复用 PRD-02 调度流程及现有 Key 配置，仅补缺口；上游已有能力优先升级/移植，不另建兜底引擎。

## 2. 业务规则

1. 管理员按模型维护可用于兜底的真实分组及能力范围、倍率。只提供能保持模型名、推理强度和关键参数的候选。
2. 用户在自己的 API Key 配置中看到可用兜底组、适用模型和倍率，主动勾选后保存授权；新 Key 和旧 Key 升级均不自动开启。
3. 高可用兜底候选＝管理员配置为可用兜底∩用户已主动开启∩支持原请求模型与能力∩当前可服务。用户不需要预先拥有普通分组访问权限。
4. 普通组顺序优先；普通候选全部因站点侧可恢复原因不可用时才尝试授权兜底。请求错误、余额不足、内容拒绝不得触发。
5. 兜底按实际服务组倍率消费，不另加隐藏兜底费用；按 PRD-01 的请求开始配置锁价，按 PRD-02 保持参数与单次结算。
6. 用户可随时关闭，关闭影响之后的新请求，不中断已经执行的请求。管理员取消某组的兜底配置或停用分组后，新兜底候选排除该组，亲和绑定不得绕过可用性检查。
7. 用户开启高可用兜底时可以看到具体倍率，之后配置页面始终展示当前有效倍率。消费记录展示本次请求锁定并实际采用的倍率。

不设置“最大可接受倍率”。管理员指定的高可用兜底角色与普通分组列表分开，不能通过普通组选项默认勾选规避主动开启。

## 3. FE 需求

| 编号 | 需求 |
|---|---|
| FE-01 | Key 编辑页单独提供高可用兜底区域，默认关闭；显示组名、适用模型、倍率和按实际组收费说明 |
| FE-02 | 主动勾选、保存、读回、取消均有明确状态；无可用候选时不显示误导性的已启用状态 |
| FE-03 | 开启时展示具体倍率，之后配置页面始终展示当前有效倍率 |
| FE-04 | 用户和管理员记录显示兜底标识、实际组、锁定倍率与 Credit 消费，用户无需知道账号凭据 |

## 4. BE 需求

| 编号 | 需求 |
|---|---|
| BE-01 | 复用模型能力与分组管理保存允许池；复用 Key 配置保存用户主动开启的状态及所选兜底组 |
| BE-02 | 保存与执行均检查 Key 归属、管理员兜底配置、用户主动开启、模型能力及当前可服务状态；服务端拒绝篡改，不引入用户分组访问权限 |
| BE-03 | 普通组耗尽后向原调度器提供已授权候选；未开启时绝不添加高倍率兜底 |
| BE-04 | 保存用户开启/关闭状态；管理员配置、默认值、数据迁移或前端隐藏字段不能代替用户主动开启 |
| BE-05 | 结算复用原账本和锁价；失败尝试不重复扣费，记录实际服务组和兜底原因 |

用户选择优先由现有 Key 字段/关联表达，仅补缺口，不创建独立审批系统。

## 5. FE / BE 验收

| 类别 | 编号 | 场景与预期 |
|---|---|---|
| FE | AC-F1 | 新旧 Key 默认未开启；用户可看到具体倍率并主动开启、关闭，刷新后状态一致 |
| FE | AC-F2 | 兜底成功记录展示实际组与对应 Credit 消费；不称为免费兜底 |
| FE | AC-F3 | 分组倍率更新后配置页面展示当前有效倍率；既有消费记录仍展示该请求采用的倍率 |
| BE | AC-B1 | 普通 A/B 均不可用且未授权时，不向高倍率组发请求 |
| BE | AC-B2 | 用户主动开启，管理员已配置且能力/可用性满足时可以兜底，无需预先拥有普通分组访问权限；模型名、推理强度与关键参数不变，按实际组结算一次 |
| BE | AC-B3 | 篡改其他用户 Key、未配置为兜底的组、停用组或不支持原请求能力的组均不能进入兜底 |
| BE | AC-B4 | 普通组仍可服务时不抢先兜底；参数/余额/审核错误不触发；关闭后新请求不能使用 |

## 6. 依赖与核查

依赖 PRD-01 价格/倍率快照及 PRD-02 责任分类与顺序调度。实施前核查实际兜底组能力、可用状态与倍率；AWSB 等渠道的可用性需通过实际服务结果验证。
