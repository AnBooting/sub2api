# PRD-03 云猫白标充值中心与卡密交付

版本：1.2｜日期：2026-10-10｜优先级：P1

## 1. 目标与范围

复用现有充值页、账户和兑换入口，将云猫商品、订单、支付和卡密能力以本站界面透出。用户看到本站商品中心、下单入口、支付体验及订单/卡密结果，不进入或感知云猫品牌、域名、页面。

本期仅建设白标展示、接口代理/适配、必要的本站用户与云猫订单关联及卡密结果展示，依据见路线文档。商品、订单、支付后台及手续费等核心业务由云猫负责，本站不重建支付、财务和资金清结算系统。参考产品形态：[ovo1.vip](https://ovo1.vip)，仅作交互参考，不作为接口能力依据；必要时允许分析、调用非公开接口。优先复用现有能力，仅补缺口。

**本期支付成功后展示卡密，不自动兑换、不自动增加余额。** 用户通过现有兑换入口兑换。旧稿 iframe、默认入账、生成已使用兑换码的方案全部替代。历史订单导入、独立补单/调账模块、订阅及并发商品不自动纳入本期。

## 2. 业务流程与规则

1. 云猫是商品唯一来源：站长在云猫后台维护商品，本站同步/代理展示新增、修改和上下架状态，仅保留必要展示快照，不要求本站重复录入价格或权益。用户看到云猫提供的 CNY 售价、数量及卡密权益；充值比例为 ¥1 获得 1 Credit。手续费及其业务规则由云猫负责，本站不另行计算或制定。
2. 用户通过本站入口调用云猫下单能力。本站只保留“本站用户↔云猫订单 ID↔商品↔当前展示状态↔卡密结果”等最小必要映射，用于找回订单、展示卡密、恢复刷新/断网查询、追踪异常和防止明显重复操作；不建立第二套完整订单/支付账本。
3. 本站展示支付所需信息；商品、订单及交付过程不能借 iframe、链接、二维码内容或资源地址暴露云猫。银行卡/支付应用的必要外部动作不等于云猫页面；具体支付方式与是否需要外部支付页面须依据真实接口确定，不能擅自扩大已确认的全程本站边界。
4. 支付结果以云猫可信接口/回调为依据，本站适配展示，不凭前端按钮、URL 参数或浏览器回跳确认成功，不自建支付状态机。
5. 云猫显示支付成功但本站卡密获取失败，展示“已支付 / 交付异常”，提示“支付已完成，但卡密暂未获取成功，请联系站长处理”，显示本站/可追踪订单号。站长通过云猫后台或接口处理，本站可复用原订单查询重试恢复展示，不要求用户重新购买。
6. 卡密就绪后本站订单详情展示并支持复制；刷新或再次查询仍为同一批卡密。用户自行兑换，支付成功至兑换前余额不变。
7. 订单结果与卡密仅允许所属用户及有权限管理员访问。云猫凭据与卡密不进入普通日志，本站不收集与展示无关的完整支付记录。
8. 商品同步失败时不删除最近一次成功商品数据，商品仍可展示，但暂停新订单创建/购买；页面提示“商品服务暂时不可用，请稍后重试”。同步恢复后恢复购买。购买限制不阻断已有订单的支付核实、查询和卡密交付；HTTP 状态或业务错误码由研发结合现有接口决定。

本站状态仅是云猫订单/支付结果及卡密获取情况的展示映射。云猫已支付结果不能因本站卡密查询失败显示为未支付；不由这些展示状态扩展独立支付账本、财务对账、退款或清结算能力。

## 3. FE 需求

| 编号 | 需求 |
|---|---|
| FE-01 | 对用户隐藏云猫品牌、页面、域名和供应商感知，以本站界面完成商品浏览、购买流程、订单查询和卡密领取；商品、售价及权益来自云猫，不在本站重复录入 |
| FE-02 | 订单列表和详情展示支付/交付状态、实付、权益与卡密；支持复制卡密并引导到现有兑换入口 |
| FE-03 | 断网、刷新、支付后返回、交付延迟时可查询原订单；不误报到账、不诱导重复支付 |
| FE-04 | 用户可见标题、错误文案、URL/跳转、嵌入页面和资源无云猫品牌/域名；内部供应商名称只在有权限管理场景使用 |
| FE-05 | 后台展示商品同步状态；同步失败时商品仍展示但暂停购买，提示“商品服务暂时不可用，请稍后重试”，恢复后恢复购买入口 |
| FE-06 | 卡密获取失败显示“已支付 / 交付异常”、本站/可追踪订单号及“支付已完成，但卡密暂未获取成功，请联系站长处理”，提供明确联系站长路径 |

## 4. BE 需求与接口边界

| 编号 | 需求 |
|---|---|
| BE-01 | 优先使用可靠公开接口；不足时在已授权店铺范围分析非公开商品、下单、支付、查单和卡密接口，凭据仅服务端保管 |
| BE-02 | 建立最小白标适配层，对接云猫商品、订单、支付结果和卡密；仅保存用户关联、结果展示、恢复查询所需映射，复用现有存储，不建设独立支付及财务系统 |
| BE-03 | 按云猫协议校验回调或通过可信服务端接口查询并映射支付结果；商品、订单金额及支付处理以云猫为准，不自行核算收款主体或资金 |
| BE-04 | 按同一云猫订单关联结果，防止前端重复操作或重复通知造成重复下单/领取等明显异常；支付与发卡由云猫负责，本站不执行自动入账 |
| BE-05 | 云猫已支付但卡密获取失败时展示交付异常并保留可追踪订单号；复用原订单查询重试，支持站长通过云猫后台/接口定位处理；用户查询检查归属 |
| BE-06 | 对接层过滤供应商品牌与敏感信息，提供本站语义接口；兑换仍调用现有能力，不在支付链执行兑换 |
| BE-07 | 保持云猫为商品主数据源，自动同步新增、修改、上下架；本站仅保存必要快照和展示数据，不提供第二套独立商品定价配置 |
| BE-08 | 商品同步失败保留最近成功数据并服务端暂停新订单创建/购买；成功恢复后恢复购买，已有订单仍可核实支付、查询和获取卡密 |

实施前核查云猫商品、下单、支付结果和卡密接口及所需协议校验，并验证卡密与现有 Sub 兑换入口的兼容性。本站不设计手续费承担规则、独立支付记录体系、退款系统、收款主体核算、财务对账或资金清结算。

## 6. 依赖、风险与上线条件

落实店铺授权资料、可信支付状态、卡密兼容性与白标支付方式后才能交付。非公开接口变更或风控可造成中断，应在现有日志与订单状态中可定位；不能暗中回退为带云猫品牌的 iframe。

接口验证优先使用测试环境。支付、手续费、退款及财务处理由云猫后台负责；本站仅保留白标体验与最小结果映射，不扩展独立支付或财务系统。
