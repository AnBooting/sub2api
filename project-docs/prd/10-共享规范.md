# S 共享规范（所有 PRD / TS 共用）

版本：1.0｜日期：2026-10-10｜适用：PRD-01～06 与 TS-01～06

本文件是**单一事实源**：术语、通用规则、质量门只在这里定义，PRD 与 TS 引用编号（如 S-3.2），不再各自重复。与 PRD 正文冲突时以 PRD 业务口径为准，并登记到 [90-评审问题与冲突](90-评审问题与冲突.md)。

## S-1 术语

| 术语 | 定义 | 代码锚点 |
|---|---|---|
| Credit | 站内额度单位。¥1 充值 = 1 Credit；源价数字直接映射同数 Credit，不换汇 | 沿用现有 quota/balance 数值字段，不缩放 |
| 源价 | 价格源给出的原币种单价（CNY 或 USD）及计量单位 | `pricing_snapshot.currency` |
| 基础 Credit 价 | 源价数字 × 计量单位归一化，未乘分组倍率 | — |
| 实际服务组 | 最终成功提供服务的分组（可能是兜底组），结算倍率取它 | 新增 `served_group_id`（C-6） |
| 请求开始时间 | 本站接收并通过基础校验的时点；锁价、峰谷判定都以它为准 | `WithGatewayTokenRequestPricing`（service/gateway_request_pricing.go:14） |
| 锁价 | 在请求开始时间固化价版本、峰谷档、候选组倍率；重试、换号、换组都不重取 | C-1 |
| 逻辑请求 | 客户端一次调用；内部可含多次上游尝试，只结算一次 | C-6 |
| 站点侧可恢复故障 | 上游账号失效/限流/满载、可安全重试的临时故障；只有它触发换号/换组/兜底 | C-5 |
| LKGP | Last Known Good Price，最近一次校验通过的价表版本 | C-2 |
| 普通组链 | Key 上用户排序的普通分组列表 | C-3 |
| 高可用兜底组 | 管理员配置、用户主动开启、普通组链耗尽后才使用的分组 | C-3 role=ha |

## S-2 计费通用规则

1. 公式唯一：`consumption_credit = actual_group_multiplier × Σ(base_credit_price_i × normalized_usage_i)`；视频按次/按秒为特例（TS-06）。
2. 缺价在调用上游前拒绝，返回 `pricing_unavailable`（C-7）。国模已是 fail-closed；USD 外模现为零成本放行（service/openai_gateway_usage.go:259-272），PRD-01 §3 未把该开关纳入本期，口径见 90 号 K-5。显式零价与缺价必须可区分：零价需在价表里有明确的 0 记录。
3. 一个逻辑请求最多一条成功结算记录。失败尝试不向用户计费。
4. 结算只读锁价快照，不读当前价表回算。历史记录缺快照时展示「缺失」，不补造。
5. 显示舍入不改变账本；沿用现有精度，不新增数值缩放迁移。

## S-3 时间

1. 数据库存 UTC（`timestamptz`）；前端按浏览器时区展示。
2. 峰谷判定使用价格数据中的 `schedule.timezone`，不得使用服务器本地时区（现有实现：service/pricing_native_cny.go:271-303）。
3. 区间一律 `[start, end)`；跨午夜区间支持 `start > end`。
4. 所有「等待时长、冷却、轮询间隔」都是配置项，不在代码里写死业务数字。

## S-4 幂等与一致性

| 场景 | 幂等键 | 规则 |
|---|---|---|
| 文本请求结算 | 逻辑请求 ID | 只写一条 usage_log；重试复用同一 ID |
| 视频任务终态 | 本站任务 ID | 终态迁移用条件更新（`WHERE status NOT IN 终态`），迟到回调不重复扣费 |
| 云猫订单 | 云猫订单号 | 本站映射表唯一约束；重复通知/查询只更新同一行 |
| 兑换卡密 | 兑换码 | 复用现有兑换逻辑，重复兑换失败 |
| 管理端写接口 | `Idempotency-Key` 头 | 复用 handler/admin/idempotency_helper.go |

## S-5 安全与隐私

1. 上游凭据、云猫凭据、卡密明文不进入普通日志、URL、前端响应（卡密仅对所属用户与有权限管理员返回）。
2. 所有用户侧查询在服务端校验资源归属（Key、订单、任务）；前端隐藏字段不构成授权。
3. 用户可见文本、URL、资源地址不得出现「云猫」品牌或域名（PRD-03）。
4. 外部价格源与云猫非公开接口返回值视为不可信输入：先校验结构、币种、单位，再生效。

## S-6 错误语义

对外错误沿用各协议现有错误格式（OpenAI / Anthropic writer），本期新增的错误码统一登记在 [11-共享契约](11-共享契约.md) C-7，禁止各模块自造同义码。HTTP 状态不是故障责任判定依据（PRD-02 §3）。

## S-7 数据变更规则

1. 迁移编号：上游最新 **245**，fork 已占 **251–258**（原 243–250，已随 0.2.17 上游同步重编号，映射表见 [上游同步说明](../上游同步说明.md)），**本期新增从 259 起**；246–250 留空，以免与上游后续发号撞号；按合入顺序领号，不改写已有迁移。
2. 每个迁移必须附回滚 SQL 或说明为何只增不减；先在数据副本演练。
3. 改 ent schema 后执行 `go generate ./ent`；改分组/Key 结构同步 `api_key_auth_cache.go` 并失效旧缓存。
4. 只增字段/表，不对 quota、balance 做批量数值迁移（PRD-01 BE-04）。

## S-8 前端规则

1. FE 不计算最终扣费、不确认支付成功、不代替 BE 做归属校验；价格预览调用 BE。
2. 新增文案 `zh` / `en` 同步，否则 `check:i18n` 失败。
3. Credit 显示按字段语义替换，不全局替换 `$`。
4. 构建按 AGENTS.md：`corepack pnpm@9 exec vue-tsc -b`、`exec vite build`，不用 `run build`。

## S-9 质量门（每个 TS 交付都要过）

| 门 | 命令 / 证据 |
|---|---|
| 后端编译 | `go build ./cmd/server` 退出码 0 |
| 后端单测 | `go test -tags=unit ./...`；已知基线失败 5 个，不得新增 |
| 前端 | `vue-tsc -b`、`vitest run`、`vite build` 全部成功 |
| 计费变更 | 给出改前/改后数值对比用例（至少覆盖 PRD 验算示例） |
| 迁移 | 数据副本升级 + 回滚演练记录 |
| 审查 | `ocr review` 或宿主审查，无凭据泄漏、无越权 |
| 交付报告 | 分「已实现 / 已验证 / 未验证」三栏，测试通过不等于已部署 |

## S-10 文档规则

1. 业务口径改动先改 PRD，契约改动先改 11 号，再改代码。
2. 现状结论必须带 `文件:行号`；无法核实的写「未核实」，不猜。
3. 编号稳定：删除的条目标「废弃」保留编号，不复用。
