# PRD-01 统一模型价格获取与 Credit 计价

版本：1.2｜日期：2026-10-10｜优先级：P0

## 1. 目标与范围

统一站内记账语义，自动获取适用模型价格，保留源币种并避免重复换算。覆盖价格管理、余额、Key 额度、消费记录、统计、限额及相关导出/API 单位说明。真实支付与源价格保持各自币种。

采用 Credit 计价，依据与范围见《需求优先级与实施路线》。不做汇率换算，不重算历史账，不新增混合币种模型系数。优先复用现有能力，仅补缺口；能配置解决的不开发，上游已有能力优先升级/移植。

## 2. 冻结规则与计算

1. 充值 ¥1 可获得 1 Credit；这是充值比例，不表示 Credit 是可兑付法币。PRD-03 的购买环节仅交付卡密，用户兑换后才增加额度。
2. 国模使用 LiteLLM 提供的 CNY 价格数据，保留 CNY 源币种，价格数字直接映射同数 Credit 基础价；外模沿用 Sub2API 当前 USD 价格源，保留 USD 源币种，价格数字直接映射同数 Credit 基础价。不要求分别抓取国内厂商或 OpenAI / Anthropic / Google 官方价格，不做汇率换算。
3. 最终消费按实际服务分组结算，不按最初选择的分组误算。多计费项分别求和：

   `consumption_credit = actual_group_multiplier × Σ(base_credit_price_i × normalized_usage_i)`

4. 源价若为每 1M tokens，则归一化用量为 `tokens / 1,000,000`；仅归一化计量单位，不换汇。输入、输出、缓存等项按该模型实际价格语义处理，禁止重复计算缓存用量。
5. 在本站首次接收并通过基础校验时记录请求开始时间并锁定模型价版本；候选分组倍率采用同一开始时点的有效配置，最终取实际服务组的倍率。内部重试不重置开始时间、不获取新价。媒体任务在提交时沿用此原则。
6. 使用现有精度与额度存储比例，确认无重复缩放后复用；显示舍入不改变账本。结算不得依赖当前已更新的价表回算。

**验算示例（仅示例，不是线上价表）**：外模源价 USD 2 / 1M tokens → 2 Credits / 1M tokens，实际组倍率 8，使用 500,000 tokens，该项消费为 `2 × 8 × 0.5 = 8 Credits`；国模 CNY 2 同样映射为基础价 2，倍率 1.2、同用量时消费 1.2 Credits。

## 3. 价格同步与异常

国内模型人民币价格统一使用 LiteLLM 提供的 CNY 价格数据，优先复用现有 LiteLLM / Sub2API 价格同步能力，不为各国内模型厂商分别建设官方价格采集接口。外模保留 Sub2API 当前 USD 价格源；优先扩展现有同步、缓存、人工价格管理和账本路径，不另建平行价格引擎。

管理员可配置模型价格同步周期，优先复用 Sub2API 当前已有 Pricing / Scheduler 配置，不新增平行调度系统，不固定在凌晨 0 点执行。

同步结果必须能识别模型/版本、来源、原币种、计量单位、维度、有效时间及基础 Credit 单价。校验 LiteLLM / Sub 返回数据的币种与单位：国模预期 `currency = CNY`，外模预期 `currency = USD`；模型、币种、计量单位异常变化不得静默覆盖当前有效价格。该校验不要求访问厂商官方接口。

LiteLLM 国模 CNY 或 Sub 外模 USD 价格源同步失败时，不覆盖 Last Known Good Price，继续使用最近一次有效价格服务，记录同步异常；优先复用 Sub2API 现有 Alert / Email 能力通知管理员。同一持续故障应合并或抑制重复通知，避免高频重复邮件，不另建告警系统。没有有效价格时不以零价冒充正常定价。

显式零价与缺价须可区分。实施前需核查当前缺价处理及兼容影响；外模零成本放行开关不属于本期新增需求，未确认的缺价策略不纳入冻结规则。

## 4. FE 需求

| 编号 | 需求 |
|---|---|
| FE-01 | 将站内余额、累计消费、请求消费、Key quota、分组限额与日/月限额按字段语义显示为 Credit；不全局替换 `$` |
| FE-02 | 充值/订单区分“实付 CNY”“卡密可兑换 Credit”“已兑换到账”，支付成功不显示为已经到账 |
| FE-03 | 价格管理区分源价格（含 CNY/USD 与计量单位）、基础 Credit 价格、分组倍率和最终售价，展示来源与同步状态 |
| FE-04 | 消费详情展示模型、实际服务组、锁定单价/倍率、用量、最终 Credit；旧记录缺快照时仅展示已有字段，不补造 |
| FE-05 | 修正相关提示、导出标题和 API 文档单位；前端价格预览使用 BE 结果，不独立实现结算逻辑 |
| FE-06 | 在现有管理配置页提供价格同步周期设置，展示最近成功同步与同步异常状态 |

## 5. BE 需求与接口语义

| 编号 | 需求 |
|---|---|
| BE-01 | 复用 LiteLLM / Sub2API 价表与同步任务，落实国模 LiteLLM CNY 数据和外模 Sub 当前 USD 数据的 Credit 映射；保留原币种，不调用汇率，不分别建设厂商价格采集接口 |
| BE-02 | 校验 LiteLLM / Sub 返回的模型、预期 CNY/USD、计量单位与完整维度；有效价格更新原子生效，异常不覆盖 Last Known Good Price，不要求调用厂商官方价格接口 |
| BE-03 | 复用额度结算，固化请求开始、价格版本、基础单价、实际服务组、倍率、用量与总消费；重试只结算一次 |
| BE-04 | 审核 API 和存储单位，保留原整数 quota 等内部比例，不以单位改名执行余额乘除或字段批量数值迁移 |
| BE-05 | 历史消费、余额与统计读取原记录；新规则以发布版本/生效时间区分，不回填虚构的历史源币种或价格快照 |
| BE-06 | 复用 Pricing / Scheduler 执行管理员配置的同步周期；失败保留有效价格继续服务，记录异常并复用 Alert / Email 通知，抑制同一持续故障的高频重复通知 |

本 PRD 指定业务语义，不指定未经核查的表名或 endpoint。既有字段能表达上述含义时复用；只有审计与结算无法表达的内容才补字段。

## 7. 依赖、风险与发布

必须核查现有模型×分组定价与存储精度。混合 CNY/USD 模型若只能统一组倍率，优先拆分经营分组；复用已有能力时不得引入隐含汇率。倍率由站长维护，平台不会随汇率自动调整商业售价。

发布前在实际数据副本核对单位映射与数值不变，并验证回滚。历史错扣属于独立账务纠错，不因 Credit 改名自动修复。PRD-02/04 提供实际服务组，PRD-05 提供峰谷基础价，PRD-06 提供媒体用量；均使用本计费契约。
