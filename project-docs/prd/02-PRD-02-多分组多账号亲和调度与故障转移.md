# PRD-02 多分组/多账号亲和调度与故障转移

版本：1.2｜日期：2026-10-10｜优先级：P0

## 1. 目标与范围

解决部分账号闲置、部分账号承载过多的问题，保留会话亲和；站点侧可恢复故障通过组内换号、普通组间切换透明处理。用户为 API Key 选择多个可用普通分组并排序，高可用兜底另按 PRD-04 主动开启。当前系统不存在用户分组访问限制。

故障分类、参数保持及全局/分组策略按以下规则执行，依据见路线文档。实施前需核查当前 Sub2API 的并发、负载、亲和和冷却实现。优先复用现有能力，仅补缺口；上游已有能力优先升级/移植，不另建健康状态体系或通用调度平台。

## 2. 调度规则

1. 请求先完成本站鉴权、余额和参数校验，并按 PRD-01 记录开始时间与锁价。停用或不支持原请求能力的分组不得进入候选；不引入用户分组访问限制。
2. 普通分组按 Key 保存的顺序尝试；先在当前组内寻找可承载原请求的账号，无账号可承载或恢复尝试耗尽后才尝试下一组。
3. 同一会话优先复用健康且有容量的有效亲和账号；亲和不绕过并发和限流。故障切换后可临时建立新的有效亲和；原优先账号恢复后，后续新请求是否回切由当前分组调度策略决定，兼顾响应速度、稳定性、缓存命中与避免频繁切号。
4. 非亲和流量根据账号实时健康状态、当前负载、并发容量及现有调度能力进行选择，避免部分账号长期闲置或部分账号持续过载。并发硬上限由原子占用与释放保证。本期不新增账号优先级、账号权重或人工权重配置；现有内部算法字段可作为实现细节复用，不形成产品能力或配置项。
5. 高优先级普通组恢复后，后续新请求重新优先使用；组内账号亲和仍适用。执行中的请求不被迁回其他组。
6. 保持模型名、推理强度及工具、结构化输出、模态等关键参数不变。协议适配只能保持等价语义，不能静默换模型或降级参数。
7. 调度依据为会话亲和、账号健康状态、当前负载/并发容量及全局/分组策略，按“全局调度策略→分组默认继承或覆盖→账号实时状态→最终调度”执行。站长选择“稳定优先、平衡、响应速度优先”等策略，不要求管理大量底层参数；等待、亲和、错误容忍和切换强度由研发结合现有能力映射，不写死秒数。策略不得放宽故障分类、并发硬上限或关键参数保持规则。

## 3. 故障分类与安全重试边界

| 故障语义 | 处理 |
|---|---|
| 上游账号/Key 失效、账号限流、满载 | 更新现有账号状态，先换号，组内无可用候选再换组 |
| 连接或上游暂时服务故障 | 能确认安全重试时同样处理 |
| 本站 Key 无效、用户余额不足、请求参数错误、用户模型名无效 | 直接返回对应错误，不换号/组 |
| 内容审核或明确业务拒绝 | 不重试，不通过换渠道绕过拒绝 |
| 超时且不能确认上游是否已执行 | 不盲目重发；优先查询/幂等机制，不能消除重复执行风险时返回明确失败 |

不按 HTTP 400/401/429/5xx 单独判定责任。例如上游账号鉴权失败与本站用户鉴权失败不同。用户指定模型有效但某个渠道不支持时，该渠道应被能力过滤；运行中暴露渠道能力不匹配，可排除该候选，不能将用户模型名错误当成站点故障。

流式响应尚未向客户端输出内容时才允许透明重试；已输出后不得重新开始并拼接结果。图片/视频有副作用或已提交任务时遵循 PRD-06，不能套用文本请求直接重发。

## 4. FE 需求

| 编号 | 需求 |
|---|---|
| FE-01 | 在现有 Key 编辑页多选可用普通分组并排序，显示倍率，保存后读回顺序一致 |
| FE-02 | 普通组与主动授权兜底分开展示，避免管理员默认链被误认为用户选择 |
| FE-03 | 用户使用记录显示实际服务组、故障转移标识与 Credit 消费，不暴露上游凭据 |
| FE-04 | 管理端优先复用账号与使用记录页面，呈现已有并发/占用/限流/亲和信息；只补定位本问题所缺字段，不默认建设独立诊断面板 |
| FE-05 | 现有管理页支持全局策略选择及分组“继承全局 / 单独覆盖”，展示当前有效策略；以稳定优先、平衡、响应速度优先表达，不要求录入大量底层参数 |

## 5. BE 需求与数据语义

| 编号 | 需求 |
|---|---|
| BE-01 | 复用 Key 分组关联并保存有序候选；服务端检查 Key 归属，过滤停用、重复和无能力的候选，不引入分组访问权限体系 |
| BE-02 | 修正实际发现的负载/并发差异，复用 Account / Scheduler / 亲和与冷却状态；成功、异常、取消均释放占用 |
| BE-03 | 区分站点故障和用户/业务拒绝；组内候选耗尽才按顺序换普通组，已失败账号不无限循环重试 |
| BE-04 | 记录逻辑请求、尝试原因和实际服务组，保留原请求关键参数；成功消费按实际组结算一次，失败尝试不额外向用户重复计费 |
| BE-05 | 普通组耗尽后仅调用 PRD-04 已授权候选；全部失败时返回准确错误，不伪造成功 |
| BE-06 | 复用策略配置和 Scheduler 实现全局默认、分组覆盖，结合账号实时状态执行；按有效策略处理临时亲和及原优先账号恢复后的新请求回切 |

旧 Key 的单一普通组转换为长度为一的顺序列表；不自动新增高倍率组。新 Key 默认普通组沿用经核实的现有规则，不能猜测线上 1x 组。Key 归属及分组可用状态在保存与执行时均校验。

## 6. FE / BE 验收

| 类别 | 编号 | 场景与预期 |
|---|---|---|
| FE | AC-F1 | Key 顺序 A→B 保存刷新仍为 A→B，倍率与 BE 一致；无用户分组访问权限门槛 |
| FE | AC-F2 | A 故障、B 服务成功，记录显示实际 B 和真实 Credit 消费；管理员能追溯转移原因 |
| FE | AC-F3 | 全局策略和分组继承/覆盖可保存、读回并展示有效策略；无需管理大量底层参数 |
| BE | AC-B1 | 当前有效亲和账号健康且有容量时按分组策略保持亲和；满载/限流后可临时换号，原优先账号恢复后的回切由策略决定，不突破并发硬上限 |
| BE | AC-B2 | A1 站点故障先尝试 A2；A 全部不可用后尝试 B；A 恢复后的新请求重新优先 A |
| BE | AC-B3 | 参数错误、本站鉴权错误、余额不足、内容拒绝均不触发第二次上游调用 |
| BE | AC-B4 | 每次尝试保持模型名、推理强度与关键参数，按实际组倍率只结算一次 |
| BE | AC-B5 | 并发、取消及异常压测中槽位释放正确；非亲和同配置账号无持续异常闲置或过载，不新增账号权重/优先级配置 |
| BE | AC-B6 | 已输出流内容不重放；不确定是否执行的超时不造成重复生成；重试在总预算内终止 |
| BE | AC-B7 | 未覆盖的组随全局策略生效，覆盖的组使用自身策略；账号实时限流/满载仍约束选号；故障后临时亲和及恢复回切符合当前组策略 |

## 7. 依赖与实施核查

依赖 PRD-01 的锁价与实际服务组结算、PRD-04 的用户主动开启。先核查实际版本的并发占用、健康状态、当前负载、亲和标识、调度策略、重试与流式输出边界；性能阈值根据真实基线确定，不因旧稿给出数字而冻结。分组切换导致价格变化必须在 Key 配置和账单可见。
