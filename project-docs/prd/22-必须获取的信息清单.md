规则 `doubao-seedance-<代际>-<档位>-<YYMMDD>`。**没有** `doubao-seedance-2-0-pro`（2.0 的 pro 级就是不带后缀的 `doubao-seedance-2-0-260128`）。
注意：**定价页用点号名**（`doubao-seedance-2.5`），与调用 ID 不是同一字符串，计费侧已做映射。

**已预留槽位（本轮已实现）**：
- 计量计划：`groups.video_price_plans["seedance"]` = `{mode, per_request_price | per_second_prices | per_token_prices}`，管理端分组表单已提供编辑器。
- 兼容旧槽位：`video_model_prices["seedance"]`。
- 模型识别：`CanonicalVideoPriceFamily()` 归一 `seedance*`、`doubao-seedance*`、`dreamina-seedance*`、点号定价名，以及 `ark/`、`volcengine/`、`bytedance/`、`dreamina/` 前缀。
- **Fail-closed**：未配置价格/模式/该分辨率档/时长/token 用量时**拒绝放行或拒绝结算**，不猜价、不回落图片价、不沿用 Grok 的 8 秒默认。
- 平面 `video_price_*` 列（xAI 每秒口径）**不再**作为 Seedance 的放行依据（它无法结算 Seedance，会导致 0 成本）。

**你需要做的**：在管理端分组表单的「视频计费计划」里为 `seedance` 选择 `per_token` 并填写各分辨率档的单价（元/百万 token，分「含输入视频 / 不含输入视频」两档）。官方参考价：2.5 → 480p/720p 70/42、1080p 77/46；2.0 → 46/28、51/31、4k 26/16（单位：元/百万 token，前者不含输入视频、后者含）。

**跨厂商预留**（同一套三模式结构，为后续模型准备）：
- **xAI Grok Imagine**：查询响应有 `video.duration` → `per_second`（现有行为，未改动）。
- **MiniMax Hailuo**：查询响应**无时长、无 usage** → `per_request`（按次）。
- 新增厂商只需在 `CanonicalVideoPriceFamily` 加前缀识别 + 在管理端填计划，无需改计费逻辑。

**管理员配置方式（已实现）**：
1. 在目标分组的编辑表单打开「可作为高可用兜底分组」；
2. 用现有**模型白名单**限定该组可服务的模型（支持通配，如 `doubao-seedance-*`，可任意添加）；
3. 用现有**费率倍数**设置该组倍率（默认 1.0）。

**用户开启方式（已实现）**：`PUT /api/v1/keys/:id/ha-groups/:groupID` 带 `{"enabled":true}` 开启，`DELETE` 同一路径关闭。倍率恒取服务端分组配置，客户端传的 `rate_multiplier` 被忽略。

**已交付**：普通组链全部耗尽且失败分类可重试时，才进入用户已授权的 HA 候选；执行前复查 PRD-04 四条件（**含管理员兜底标记**，所以管理员取消后存量授权立即失效）；平台、模型白名单、Claude Code 限制与普通组同一套策略，HA 不能绕过。

> **已知边界**：HA 候选目前只接入 `/v1/responses`；`/v1/messages`、`/v1/chat/completions`、Gemini 入口尚未接入 HA（普通组链正常，只是不会兜底）。如需覆盖请确认。
