# PRD-06 图片/视频中转与多维计费能力

版本：1.2｜日期：2026-10-10｜优先级：P2

## 1. 目标与范围

将现有图片站已有的图片透传与计费能力迁回 Sub2API，优先复用现有实现，不重新开发完整图片系统。新增视频请求透传与计费，统一使用站内 Key、分组、Credit 与消费记录。图片以现有站点实际能力和调用样例界定范围；视频 Seedance 为首批候选，具体版本/渠道在实施前核实。

图片回迁和视频透传计费按以下范围执行，依据见路线文档。兼容 new-api 以迁移清单的真实调用格式和目标 Provider 协议为边界。优先复用现有能力，仅补缺口；能配置解决的不开发，上游已有能力优先升级/移植。

本期包含中转、必要任务状态及计费配置/查询；不建设对象存储，不开发生成画布、素材编辑器或新用户端生成工作台。

## 2. 迁移与透传规则

1. 盘点图片站实际模型、接口、鉴权、请求/响应、结果形式和计价维度；复用其已有适配实现，再接入 Sub 的鉴权、分组与账本。用户调用所需变动明确列入迁移说明。
2. 视频按首批确认的实际厂商/渠道协议透传创建、查询与结果，保留模型、关键参数、上游状态和必要错误语义；鉴权替换仅发生在 BE。
3. 异步视频建立本站任务与用户、实际分组、上游任务/账号的归属关系，后续查询仍回到原任务渠道；不能每次查状态重新调度。
4. 复用已有任务能力；确无能力时只补该批协议要求的最小生命周期。仅靠客户端查单会漏结算时，必须采用可靠回调或服务端查询推进终态。
5. 上游已接受任务或执行状态不明时，不盲目换号/换组重提；使用幂等或任务查询确认。客户端重复提交需有可追溯的请求/任务关联，避免重复生成。
6. 本期不建设对象存储。根据目标 Provider 实际协议，支持无需本站持久化媒体文件的中转方式，包括上游 URL 透传、流式代理、二进制代理、异步任务结果代理；不要求所有 Provider 同时提供四种方式。结果有效期及不可访问状态按真实协议表达。未知模型或缺少本次计费所需价格时不调用上游。

## 3. 图片现有计费与视频首期模式

| 项目 | 规则 |
|---|---|
| 价格来源与单位 | 国模 basellm CNY 价格源，外模 Sub 当前 USD 价格源；数值映射 Credit、不换汇；原币种、计量单位保留；复用现有同步能力，不分别建设厂商价格采集接口 |
| 图片 | 继续沿用现有图片站已经存在的实际计费维度，不重新设计图片价格体系 |
| 视频模式粒度 | 唯一键为模型×分组；`per_request` 与 `per_second` 二选一；同模型在不同组可不同模式 |
| 视频范围 | 本期仅冻结按次/按秒；首批 Provider 的真实协议或价格规则必须依赖额外维度时，仅补该 Provider 的最小必要适配，不预建通用多维视频计费系统 |
| 按次 | `base_credit_per_request × actual_group_multiplier × billable_request_count` |
| 按秒 | `base_credit_per_second × actual_group_multiplier × billable_seconds` |
| 锁价 | 提交开始锁定模式、适用单价版本和候选组配置；最终取实际接受任务分组；查询与配置更新不改变已提交任务 |

配置示例：`Seedance + Group A → per_request`，`Seedance + Group B → per_second`；`Seedance + Group A` 不能同时为 `per_request + per_second`。

按次计量的“次”是计价契约定义的可计费生成单元，不是创建 API 调用、内部重试、轮询或回调次数；不能对查询扣生成费。按秒所用时长必须有明确可信来源：上游可计费时长优先，不具备时需在接入时明确可验证的请求时长规则，不把墙钟等待时间当视频时长。不新增 N 秒阈值、阶梯计费或其他复杂计费规则。

模式是平台售价配置，不能因为上游按秒收费就强制所有分组按秒售卖；不得修改 basellm / Sub 源价金额后冒充原始源价。如源价与平台模式单位不同，仅按目标 Provider 实际规则补最小必要的可复算适配，未明确单价依据的组合不得上线售卖。

## 4. 结算与余额（实施方案）

优先复用 Sub2API 已有预扣/额度保留能力；若现有能力不足，则按目标视频协议采用最小充分的余额校验与结算方案，不因本需求建设通用资金冻结系统。已有预扣/保留适用时，提交前校验余额并保留可核定额度，成功后按锁价与实际计量结算，失败释放保留额度。不允许客户端是否查询决定是否扣费。

无法核定时长上限、超出保留额度或上游最终用量不明时，需落实该模型的计量与余额处理政策后接入；不默认新增欠费经营规则。对超时但上游仍可能执行的任务，记录待核实状态，不因本地超时直接当失败并重新生成。终态处理幂等，迟到回调不得造成重复扣费。

失败/取消/部分成功按目标协议及已确认计价契约处理，实施前核实任务终态与结算边界；不额外设置固定超时或保留周期作为产品要求。

## 5. FE 需求

| 编号 | 需求 |
|---|---|
| FE-01 | 管理端在现有模型/分组配置中选择视频按次或按秒模式并显示单价单位；同一模型×组不能同时选两种模式，不提供通用多维视频价格配置 |
| FE-02 | 价格预览区分源价、基础 Credit 单价、模式和组倍率；图片沿用既有计费维度，视频额外展示仅限实际 Provider 必需的最小适配 |
| FE-03 | 在现有任务/使用记录中展示模型、实际分组、状态、模式、计量与消费；必要时补最小查询页，不扩展为画布 |
| FE-04 | 提供首批已验证的 API 调用说明与结果查询方式；未接入候选不显示为可用 |

## 6. BE 需求

| 编号 | 需求 |
|---|---|
| BE-01 | 复用现有图片透传/计费及 Sub 鉴权/分组能力；视频按 Provider 协议采用 URL、流式、二进制或异步结果代理，仅补首批必要缺口，不持久化媒体文件 |
| BE-02 | 对模型×组保存唯一按次/按秒模式及适用单价，拒绝并存模式、错单位、缺价或非法修改；其他维度仅按首批 Provider 必要性最小适配，不建设通用多维视频计费系统 |
| BE-03 | 任务归属、上游任务关联、锁价和计费量可追溯；查询鉴权不泄露其他用户任务或上游凭据 |
| BE-04 | 回调/服务端查询可靠推进终态；优先复用预扣/额度保留，不足时采用目标协议所需最小余额校验与结算，保证数据一致和幂等，不建设通用资金冻结系统；轮询、重试不产生生成消费 |
| BE-05 | 与 PRD-02 共享安全重试边界；已受理任务不跨组重复生成，结算按原接受任务组倍率 |

## 7. FE / BE 验收

| 类别 | 编号 | 场景与预期 |
|---|---|---|
| FE | AC-F1 | 同模型组 A 配按次、组 B 配按秒可保存；组 A 不能同时配置两种模式，单位展示清楚 |
| FE | AC-F2 | 任务详情显示创建、终态、锁定模式、计量与实际组；不以当前配置覆盖旧任务 |
| BE | AC-B1 | 迁移清单中的图片典型请求在 Sub 成功，响应/图片结果符合原调用契约，消费可独立复算 |
| BE | AC-B2 | 首批确认视频完成“创建→查询/回调→结果→结算”；客户端从不查询仍正确结算 |
| BE | AC-B3 | 示例测试价：A 按次 3 Credits、倍率 2、1 次＝6 Credits；B 按秒 0.5 Credits、倍率 2、10 秒＝10 Credits；同模型两组分别正确结算 |
| BE | AC-B4 | 模式或价表更新不改变已提交任务；重复回调/轮询只结算一次；其他用户不能查询结果 |
| BE | AC-B5 | 缺少适用单价的请求不发往上游；明确失败按契约处理额度，使用保留能力时正确释放；不确定超时不重复提交 |
| BE | AC-B6 | 按秒时长来源可复核；按次不按轮询次数累加；已受理任务的查询不重新换组，不使用 N 秒阈值或阶梯计费 |
| BE | AC-B7 | 按目标 Provider 实际协议验证适用的 URL、流式、二进制或异步结果代理，结果正确且无需本站持久化媒体文件 |

## 8. 依赖与首批接入条件

依赖 PRD-01 的 Credit 与快照契约、PRD-02 的安全调度。实施前落实图片迁移清单和脱敏样例、Seedance 版本/渠道及适用 basellm CNY 价格数据、Provider 中转协议、按次/按秒单价、时长来源及现有余额校验/预扣能力。分辨率、质量等额外维度仅在首批实际 Provider 必需时补最小适配；先迁移图片并验收，再开放协议与计价契约完整的首批视频。
